## 과거 기록 및 옛 문서 보존 규칙

- 기존 `learning/records/01-01.md`, `01-03.md`, `01-04.md`, `01-05.md` 등은 **작성 당시 주제로 작성된 역사 기록**입니다. 삭제하거나 새 Lab을 완료한 증거로 둔갑시키지 않습니다.
- 이전 교안은 Git 히스토리에서 재현할 수 있습니다. 커리큘럼에서 빠진 옛 교안 파일은 혼동을 방지하기 위해 `legacy` 안내를 삽입하여 활성 인덱스에서 제외합니다.
- 이전 성적은 `learning/progress.md`의 **구 과정 학습 이력**에서 보존합니다.
- 새 01-03 같은 주제가 합쳐진 Lab의 **신규 점수는 미평가**. 이전 평가를 참고자료로 활용할 수는 있지만 전체 신규 Lab 완료 판정에는 실제 증거 필요.
- **기록 충돌 방지:** 새 과정에서 주제가 변경된 Lab의 새 학습 기록은 `learning/records/v2/<id>.md`에 작성한다. 예전 `learning/records/01-03.md`와 `01-05.md`는 그대로 보존한다.
- 실제 GPU는 아직 실행하지 않았습니다. 프로젝트의 비용·성능·장애 복구 결과는 미검증 상태입니다.

## 실제 사례 검증 규칙

- 실제 기업 자료는 [references.md](references.md)에 출처 유형을 포함해 기록.
- 자연 사고의 원인과 우리가 통제한 OOM·Job/Node 중단·설정 오류의 원인을 혼동하지 않음.
- 대규모 504 GPU 환경에서 발생한 NFS I/O 문제를 GPU 1~2대 S3/EBS에서 동일 재현했다고 주장하지 않음.
