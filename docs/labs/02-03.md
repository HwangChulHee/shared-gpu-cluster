# Lab 02-03 — YOLO DataLoader·Checkpoint 기본 운영

> **2026-11-13 Linux GPU 서버 중심 교안** · 환경: **L+G1** · 실제 GPU 실험 미완료. [이관표](../migration-2026-11-13.md)에서 이전 번호를 확인한다.

## 실제 운영 요구와 학습 목적

GPU 학습은 CPU 데이터 준비와 모델 상태 저장을 함께 고려해야 한다. 학습 재개는 Kubernetes가 아니라 YOLO 워크로드가 구현/호출해야 한다.

## 내부 동작·책임 분리

`데이터셋(EBS) → DataLoader 읽기/디코드/증강 → CPU 메모리 → GPU 학습 → 로컬 Checkpoint → S3 보존 → 앱 Resume`

## 학습 및 직접 실습

1. 기존 01-05 YOLO 학습 이론을 재사용해 workers, batch, imgsz, cache, epoch와 Checkpoint가 포함하는 상태 설명.
2. 01-03에서 검증한 YOLO 이미지/데이터 사용. workers·cache·batch를 **하나의 정상 설정으로 고정**하여 데이터 준비 시간과 짧은 학습을 기록.
3. YOLO 기본 Checkpoint 생성 위치·파일 크기/쓰기 시간 확인 후 S3로 보존. 실패한 업로드가 정상 파일로 오인되지 않도록 검증.
4. 별도 실행에서 체크포인트를 읽고 `resume`이 실제 Epoch/옵티마이저 상태를 어떤 범위까지 복원했는지 로그로 검증.
5. 실패 시 OS/컨테이너 재시작과 학습 재개가 독립임을 기록. **성능 튜닝·비교 실험은 Phase 06-02**로 미룸.

## 완료 판정에 필요한 실제 증거

학습 정상 로그, 고정된 DataLoader 설정·데이터/CPU 사용·Checkpoint 생성/S3 저장/재개 기록.

GPU/EKS 실행 전 **G/VT 쿼터 8 vCPU 적용 확인**과 별도로 EC2 AZ 용량·AMI·실제 가격·EBS/S3/NAT/IPv4 부대 비용·리소스 삭제 계획을 검토한다. 준비되지 않으면 L 이론만 진행하고 GPU 실습은 **대기**로 표시한다. 예상과 실제 출력은 구분한다.

## 서술형 질문 (답변 후 다음 개념)
