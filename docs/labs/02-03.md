# Lab 02-03 — Kubernetes GPU 자원 등록

> **학습 교안 / 미실행**. 실행 절차는 실제 AWS/패키지 버전에 맞춰 고정한 뒤 수행합니다. 예상 결과는 실측 결과가 아닙니다.

## 학습 맥락과 목표

GPU 노드는 Ready이고 `nvidia-smi`가 정상인데 Allocatable이 0이라면 노드 전체 장애보다 Device Plugin 로그와 등록 상태가 우선 진단 대상이다.

## 핵심 개념·원리

1. 호스트 Driver와 Container Toolkit이 정상이어도 Kubernetes의 `nvidia.com/gpu` 자원은 자동으로 생기는 것이 아니다. NVIDIA Device Plugin이 GPU 장치를 탐지하고 kubelet의 Device Plugin API로 자원을 등록한다.

2. Scheduler는 노드 Capacity/Allocatable에 표시된 GPU 자원을 보고 요청을 배치한다. Runtime이 실제 컨테이너에 장치 파일·라이브러리를 주입하는 것은 배치 이후 단계다.

3. AL2023 NVIDIA EKS 최적화 AMI는 Driver/Toolkit 포함 구성을 확인하고, Device Plugin은 별도 배포하는 경로를 우선 검토한다. 다른 AMI에서는 포함 구성 자체가 다를 수 있다.

## 내부 흐름

물리 GPU → NVIDIA Driver/NVML → Device Plugin → kubelet GPU Capacity/Allocatable → Scheduler 자원 배치 → Container Runtime/Toolkit → GPU 작업 실행.

## 실습 준비

AMI·드라이버·툴킷·플러그인 버전과 노드 접근 방법 기록. Operator와 Device Plugin의 중복 관리 회피.

## 실습

1. 노드별 `kubectl describe node`의 GPU Capacity/Allocatable 확인.
2. Device Plugin DaemonSet 상태/로그와 노드별 호스트 GPU 인식 결과를 비교.
3. `resources.limits: {nvidia.com/gpu: 1}`를 가진 두 Pod를 서로 다른 GPU 노드에서 동시 실행해 실제 GPU 사용 확인.

## 검증할 증거

- K8s Node 자원, Plugin 로그, 컨테이너 GPU 출력 3종 연결
- Device Plugin 제거/오류가 기존 Pod 및 신규 스케줄링에 미치는 영향을 개념적으로 설명

## 서술형 인출 질문

1. `nvidia-smi` 정상·Allocatable 0이면 어느 계층을 의심하는가?
2. Scheduler와 Container Toolkit은 GPU 할당 과정에서 각각 무엇을 하는가?

## 실습 확장: 계층별 진단 명령

**실행 위치: EKS 접근 권한을 가진 터미널(G2).** Node/DaemonSet 명칭은 실제 출력에서 확인한다.

```bash
kubectl get nodes -o wide
kubectl describe node <GPU-NODE-NAME>
kubectl get daemonsets -A
kubectl get pods -A -o wide
```

`<GPU-NODE-NAME>`은 실제 노드 이름으로 치환한다. `describe node`에서 `Capacity`와 `Allocatable`의 `nvidia.com/gpu` 값을 확인한다. 확장 리소스가 **누락**된 것과 **0으로 보고**되는 것은 다른 관측이므로 구분한다.

1. **호스트 관측:** `nvidia-smi`가 성공하는가?
2. **Plugin 관측:** NVIDIA Device Plugin DaemonSet의 원하는 Pod 수와 실제 Ready 수가 일치하는가? 해당 Pod 로그는 `kubectl logs -n <namespace> <plugin-pod>`로 확인.
3. **Kubelet 관측:** Node에 GPU Capacity/Allocatable이 보고되는가?
4. **배치 관측:** GPU 1개 limit을 요청하는 Pod가 실제 GPU 노드에 배치되는가? 불가능하면 Pod Events에서 원인을 확인.
5. **연산 관측:** Pod 내부에서 GPU 장치 사용이 가능한가?

**진단 표(미실행 예시)**

| 호스트 GPU | K8s GPU 등록 | GPU Pod 실행 | 우선 확인 |
|---|---|---|---|
| 실패 | 없음 | 실패 | Driver/AMI/장치 |
| 성공 | 없음 | 대기 | Device Plugin/kubelet |
| 성공 | 있음 | 컨테이너 실행 실패 | Runtime/Toolkit/이미지 |

Device Plugin 설정 변경은 기존 Pod에 영향을 줄 수 있으므로 장애 재현은 [Lab 06-03](06-03.md)의 통제된 세션에서 수행한다.
