# Lab 06-01 — 정상·동시 부하 실험

> **학습 교안 / 실행 전**. 아래 예시는 실제 테스트 결과가 아닙니다.

## 이 Lab을 배우는 이유

Gemma 서버를 상시 띄운 채 배치 3개를 요청하면 가용한 GPU는 1개뿐일 수 있다. 배치 풀 공유 실험과 사용자 채팅 서비스 실험을 별개로 진행한다.

## 핵심 개념과 내부 원리

1. 단일 팀 정상 작업은 장애 실험의 대조군이다. 동일 입력·GPU·모델 버전·캐시 상태와 작업 제출 간격을 기록해야 정책 변경 효과를 비교할 수 있다.

2. 두 GPU에 세 팀 Job을 제출할 때 세 번째 작업이 대기할 수 있다. 여기에 Gemma 지속형 서비스와 세 배치 Job을 섞으면 GPU 요청량과 대기열 조건이 달라진다.

3. 부하를 늘린 결과는 처리량, 대기시간, 응답 p95, 실패율, GPU 사용률을 함께 해석해야 한다. GPU 사용률만 높다고 서비스가 성공한 것은 아니다.

## 시스템 동작 흐름

실험조건 고정 → 단독 T01 기준선 → 3팀/2GPU T02 → 요청량 증가 T03 → 각 구간의 K8s/서비스/GPU 지표 수집 → 통제된 비교.

## 실습 전 준비

T01·T02·T03 입력/모델/동시성·실행시간·데이터 크기 고정, 시간 기록·측정 스크립트·대시보드 사전 준비.

## 직접 실습

1. T01에서 세 워크로드를 각각 반복 실행해 기본 지표 수집.
2. T02는 종료형 GPU Job 3개를 동시에 제출해 2개 점유/1개 대기를 관찰.
3. T03은 Gemma 동시 프롬프트 또는 Job 제출량을 단계적으로 늘려 지연·실패율을 비교.

## 검증 기준과 남길 증거

- 실측 로그·메트릭·실험 입력 및 반복 횟수 기록
- 실시간 서비스 용량과 배치 풀 용량을 혼합해 결론 내리지 않음

## 서술형 인출 질문

1. T02의 공정성 결과가 T03의 Gemma 추론 서비스 지연과 같지 않은 이유는?
2. GPU Util 90%와 사용자의 p95 응답 지연이 함께 높다면 좋은 운영 상태인가?
