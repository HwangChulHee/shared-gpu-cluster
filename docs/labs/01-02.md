# Lab 01-02 — GPU 사전 용량·비용·쿼터

> **학습 교안 / 실행 전**. 예시와 예상 동작은 실측 결과가 아닙니다. 학습 시작 시 [진도표](../../learning/progress.md)에서 상태 확인.

## 왜 배우는가

실습을 진행하기 전에 인스턴스 비용과 쿼터를 확인해야 GPU 사용 제한 및 예상치 못한 요금으로 학습이 중단되지 않는다.

## 핵심 개념

1. GPU 인스턴스 가격은 GPU 사용률이 아니라 인스턴스 할당 시간에 주로 비례한다. EKS Control Plane, NAT Gateway, CPU 노드, 저장소 등은 GPU를 꺼도 과금될 수 있다.

2. EC2 GPU 인스턴스의 GPU 메모리, GPU 수, vCPU, 시스템 RAM, 지원 AMI를 함께 비교해야 한다. 초기에 전체 GPU 단위 공유를 검증하므로 서로 다른 GPU Worker에 GPU 한 장씩 배치할 수 있는 구성을 우선 검토한다.

3. 계정 Service Quotas 한도와 특정 AZ의 실제 생성 가능 여부는 다르다. 쿼터가 충분해도 해당 시점·AZ에서 인스턴스가 부족할 수 있다.

## 내부 동작 흐름

모델/워크로드 메모리 요구 추정 → 인스턴스 후보 → 리전/AZ 가용성·쿼터 → GPU/비GPU 고정비 산정 → 1회 세션 예산 → 구축/삭제 계획.

## 실무·프로젝트 예시

단일 GPU EC2 실습에는 EKS Control Plane이 불필요하다. GPU 검증을 Phase 01에서 먼저 끝낸 다음 EKS에 진입하면 비용도 줄고 오류 원인도 분리된다.

## 실습 전 준비

AWS 콘솔의 리전, Service Quotas, EC2 GPU 인스턴스 및 On-Demand Pricing 확인. 현재 값만 기록하고 문서에 고정가격을 일반화하지 않음.

## 직접 해볼 실습

1. Gemma 4 모델 후보의 양자화별 VRAM 요구량을 GPU 인스턴스 후보와 비교.
2. G1(단일 GPU EC2), G2(EKS+CPU 노드+GPU 2대) 세션 비용표 작성. 예상 가동시간과 잔여 리소스 요금 포함.
3. destroy 후 점검할 EKS, EC2, EBS, EFS, NAT, LB, Elastic IP, CloudWatch, S3 항목 체크리스트 작성.

**주의:** G1 실습은 EC2 가동시간·쿼터·사용 리전을 먼저 확인하고, 결과 보존 후 인스턴스를 정리합니다. 세부 명령·컨테이너 태그는 실습 시점의 실제 AMI 및 버전에 맞춰 고정합니다.
