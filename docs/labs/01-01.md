# Lab 01-01 — GPU 컴퓨팅 기초

> **학습 교안 / 실행 전**. 예시와 예상 동작은 실측 결과가 아닙니다. 학습 시작 시 [진도표](../../learning/progress.md)에서 상태 확인.

## 왜 배우는가

GPU가 빠르다는 말은 모든 코드가 빨라진다는 뜻이 아니다. 수많은 연산을 동시에 처리할 수 있는 데이터 병렬 작업에 유리하지만, 전송량과 메모리 접근이 병목이면 GPU 계산 유닛은 쉬고 있을 수 있다.

## 핵심 개념

1. CPU는 낮은 지연시간으로 다양한 제어 흐름을 실행하는 데 유리하고, GPU는 다수의 유사 연산을 병렬 처리하는 처리량 지향 장치다. 추론과 학습은 행렬 연산이 많아 GPU를 사용하지만, 입력 디코딩·전처리·네트워크 호출은 CPU 비중이 높을 수 있다.

2. VRAM은 GPU에 직접 탑재된 메모리다. 모델 가중치뿐 아니라 활성화, 학습 옵티마이저 상태, 추론 KV 캐시도 공간을 사용한다. GPU가 16GiB라고 16GiB 모델을 그대로 올릴 수 있다고 판단하면 안 된다.

3. PCIe는 호스트와 GPU 사이의 데이터 이동 경로다. 작은 데이터를 자주 전송하면 연산속도보다 복사 오버헤드가 더 커질 수 있다. 서버 내 GPU 여러 대의 상호 연결과 노드 간 네트워크는 서로 다른 계층이다.

## 내부 동작 흐름

입력 데이터(스토리지/네트워크) → CPU 로딩·전처리 → 호스트 RAM → PCIe → GPU VRAM → GPU 커널 실행 → 결과 복사/저장. 한 단계가 느리면 GPU 사용률은 낮아도 전체 작업시간은 길다.

## 실무·프로젝트 예시

YOLO의 이미지 디코딩이 느리면 GPU 계산 자체는 빨라도 학습은 지연된다. Gemma는 모델이 VRAM에 적재된 뒤에도 긴 문맥과 동시 요청 때문에 메모리가 더 필요할 수 있다. XGBoost는 데이터셋을 GPU에 올리는 시점의 메모리가 중요하다.

## 실습 전 준비

CPU·GPU 역할, VRAM과 RAM, GPU 사용률과 GPU 할당 여부를 두 열로 비교표 작성.

## 직접 해볼 실습

1. 세 워크로드의 데이터 흐름을 그림으로 표현하고 CPU/GPU/스토리지 단계 표시.
2. GPU VRAM 16GiB, 모델 가중치 14GiB라는 가상 사례에서 추론 실패 조건 3개 추론.
3. GPU Util 15%이지만 작업이 느린 상황의 진단 순서 작성.

**주의:** G1 실습은 EC2 가동시간·쿼터·사용 리전을 먼저 확인하고, 결과 보존 후 인스턴스를 정리합니다. 세부 명령·컨테이너 태그는 실습 시점의 실제 AMI 및 버전에 맞춰 고정합니다.

## 검증 및 산출물

- 데이터 흐름에서 메모리와 연산/전송 병목을 구분
- 가중치 크기만으로 메모리 적합성을 판단하지 않음

## 서술형 인출 질문 (학습 후 답변)

1. 왜 CPU 사용률이 높고 GPU 사용률이 낮은데 학습이 느려질 수 있는가?
2. 모델 가중치가 VRAM보다 작다는 정보만으로 Gemma 추론 가능 여부를 판단할 수 없는 이유는?
