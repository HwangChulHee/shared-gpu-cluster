# Lab 04-01 — 부서별 사용자 흐름·UI

> **사전 학습 교안 / 미실행**. 학습 도중 사용한 실제 버전·명령어·관측값은 별도의 학습 기록에 남깁니다.

## 학습 목표와 상황

YOLO 학습 요청 버튼을 누른 직후 성공했다고 표시하면 Job이 Pending인 상태를 숨기게 된다. 접수, 대기, 실행, 완료를 분리 표시한다.

## 핵심 개념

1. Gemma 채팅은 요청마다 HTTP 응답을 주는 실시간 추론 UX다. YOLO/XGBoost는 분 단위 학습 Job을 실행하므로 `202 Accepted` 및 Job ID를 반환하고 사용자는 상태를 조회하는 비동기 UX가 적합하다.

2. UI는 실제 클러스터 상태를 보이는 목적이 아니라 부서가 AI 워크로드를 사용하는 경험을 제공한다. 클러스터 자원 메트릭은 Grafana에 맡긴다.

3. 실행 대기/진행/성공/실패 상태와 모델·데이터 버전을 표시해야 인프라 장애와 앱 실패를 구분할 수 있다.

## 내부 동작 경로

사용자 선택/입력 → React 폼 검증 → FastAPI 호출 → Chat 응답 또는 Job ID → 주기적 상태 조회 → 결과 화면.

## 실습 준비

React/Vite 최소 프로젝트, UI별 입력 형식과 예제 데이터셋·보여줄 결과 정의.

## 직접 수행할 실습

1. Gemma 채팅에 입력/응답 및 에러 처리 구현.
2. YOLO 학습에 데이터셋·epoch 선택, Job ID·진행 상태·예측 이미지 표시.
3. XGBoost에 데이터셋 선택, 진행 상태·평가 지표 표시. 백엔드가 없어도 로컬 mock으로 화면 테스트.

## 검증·완료 기준

- 세 화면이 실제 부서용 작업 흐름임을 시연
- 모든 상태에 오류·대기·재시도 안내

## 서술형 질문

1. Gemma 채팅과 YOLO 학습을 같은 동기 HTTP 방식으로 구현하면 어떤 문제가 생기는가?
2. Job API가 202를 반환했는데 왜 학습이 성공했다고 표시하면 안 되는가?
