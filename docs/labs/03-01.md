# Lab 03-01 — NVML·DCGM을 통한 GPU 관측

> **2026-11-13 Linux GPU 서버 중심 교안** · 환경: **G1** · 실제 GPU 실험 미완료. [이관표](../migration-2026-11-13.md)에서 이전 번호를 확인한다.

## GPU 비용 최적화 실행 구간

> 공통 기준: [GPU 실행 게이트·G1/G2 런북](../gpu-execution-gates.md). **OFF 준비가 완료되어도 GPU 실측을 완료한 것은 아니다.** 실제 출력과 가설/계획을 구분한다.

| 구간 | 수행할 작업·완료 기준 |
|---|---|
| **GPU OFF-1 · 사전 학습/로컬 검증** | NVML/nvidia-smi·DCGM GPU Util/VRAM/전력 정의, 쿼리·샘플링 스크립트·시간축 설계 |
| **GPU ON · 최소 시간 실측** | G1 실제 지원 필드 확인·GPU 가동 중 nvidia-smi/DCGM 메트릭 원본 수집 |
| **GPU OFF-2 · 분석/기록** | GPU Util·VRAM·전력 시계열과 샘플링 한계 해석 |

GPU가 필요한 실측은 각 세션에서 이미 준비된 명령·성공 기준·결과 저장 경로를 사용한다. 실패하면 원인 계층과 시간을 기록하고 사전 중단 조건을 적용한다.

## 실제 운영 요구와 학습 목적

GPU 메모리 점유와 GPU Utilization은 다르다. 드라이버·장치 상태에 대한 측정 출처와 의미를 이해해야 성능 문제를 판단할 수 있다.

## 내부 동작·책임 분리

`GPU/Driver → NVML(nvidia-smi) 또는 DCGM → GPU Util·VRAM·전력·온도·프로세스 측정`

## 학습 및 직접 실습

1. NVML, nvidia-smi, DCGM, CUDA 연산 지표의 역할을 구분하고 GPU Util이 연산 포화율 그 자체가 아닌 이유 설명.
2. G1에서 `nvidia-smi`, `nvidia-smi --query-gpu=timestamp,name,utilization.gpu,memory.used,memory.total,temperature.gpu --format=csv` 등 실제 지원 쿼리 확인.
3. YOLO 시작/학습/종료 구간에서 일정 간격으로 GPU 지표 측정. 평균·최대 VRAM 및 표본화 한계를 명시.
4. 관련 DCGM 지표 정의/익스포터 지원 상황을 확인. 단일 서버 메트릭 파이프라인 설치는 03-02에서 수행.
5. GPU가 할당되었지만 낮은 Util 또는 높은 VRAM 점유만으로 결론을 내리지 않고 CPU·데이터 지표와 연결.

## GPU OFF-1 수집 스크립트 준비

- [`scripts/collect-gpu-metrics.sh`](../../scripts/collect-gpu-metrics.sh): G1에서 `nvidia-smi` 지원 필드를 선행 조회한 뒤 일정 간격으로 timestamp·GPU Util·VRAM·온도·전력·SM 클럭을 CSV에 저장.
- GPU 없는 WSL에서 `bash -n scripts/collect-gpu-metrics.sh`로 구문 검사 가능. 실제 `nvidia-smi` 및 CSV 측정 성공은 **GPU ON 전까지 미검증**으로 유지.
- 실행 예: `./scripts/collect-gpu-metrics.sh 60 1` (60개 수집 라운드, 각 호출 완료 후 약 1초 휴식; 정확히 매초 1회 측정하는 실시간 스케줄러는 아님).
- 기본 결과: `artifacts/gpu-metrics/` (Git 제외). GPU ON 종료 전에 결과를 외부에 안전하게 백업해야 함.
- 출력은 nvidia-smi의 **시점 표본**이며 `GPU Util`의 자체 집계 창은 호출 간격과 동일하지 않음. DCGM SM/Tensor/DRAM 지표는 03-02 준비/실측에서 별도로 다룸.

## 완료 판정에 필요한 실제 증거

실제 GPU 상태 출력, 샘플링 간격·학습 구간 매핑, GPU Util/VRAM 구분 설명.

GPU/EKS 실행 전 **G/VT 쿼터 8 vCPU 적용 확인**과 별도로 EC2 AZ 용량·AMI·실제 가격·EBS/S3/NAT/IPv4 부대 비용·리소스 삭제 계획을 검토한다. 준비되지 않으면 L 이론만 진행하고 GPU 실습은 **대기**로 표시한다. 예상과 실제 출력은 구분한다.
