# Lab 03-01 — NVML·DCGM을 통한 GPU 관측

> **2026-11-13 Linux GPU 서버 중심 교안** · 환경: **G1** · 실제 GPU 실험 미완료. [이관표](../migration-2026-11-13.md)에서 이전 번호를 확인한다.

## 실제 운영 요구와 학습 목적

GPU 메모리 점유와 GPU Utilization은 다르다. 드라이버·장치 상태에 대한 측정 출처와 의미를 이해해야 성능 문제를 판단할 수 있다.

## 내부 동작·책임 분리

`GPU/Driver → NVML(nvidia-smi) 또는 DCGM → GPU Util·VRAM·전력·온도·프로세스 측정`

## 학습 및 직접 실습

1. NVML, nvidia-smi, DCGM, CUDA 연산 지표의 역할을 구분하고 GPU Util이 연산 포화율 그 자체가 아닌 이유 설명.
2. G1에서 `nvidia-smi`, `nvidia-smi --query-gpu=timestamp,name,utilization.gpu,memory.used,memory.total,temperature.gpu --format=csv` 등 실제 지원 쿼리 확인.
3. YOLO 시작/학습/종료 구간에서 일정 간격으로 GPU 지표 측정. 평균·최대 VRAM 및 표본화 한계를 명시.
4. 관련 DCGM 지표 정의/익스포터 지원 상황을 확인. 단일 서버 메트릭 파이프라인 설치는 03-02에서 수행.
5. GPU가 할당되었지만 낮은 Util 또는 높은 VRAM 점유만으로 결론을 내리지 않고 CPU·데이터 지표와 연결.

## 완료 판정에 필요한 실제 증거

실제 GPU 상태 출력, 샘플링 간격·학습 구간 매핑, GPU Util/VRAM 구분 설명.

GPU/EKS 실행 전 **G/VT 쿼터 8 vCPU 적용 확인**과 별도로 EC2 AZ 용량·AMI·실제 가격·EBS/S3/NAT/IPv4 부대 비용·리소스 삭제 계획을 검토한다. 준비되지 않으면 L 이론만 진행하고 GPU 실습은 **대기**로 표시한다. 예상과 실제 출력은 구분한다.

## 서술형 질문 (답변 후 다음 개념)

VRAM을 대부분 점유하지만 GPU Utilization이 낮을 때 무엇을 알 수 있고 무엇은 알 수 없을까?
