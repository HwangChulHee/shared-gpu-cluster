# Lab 03-01 — S3·EBS·로컬 데이터 경로

> **새 21 Lab 커리큘럼의 교안 / 실측 전** · 환경: L+G1. 이전 29 Lab에서 같은 번호를 사용했다면 [이관표](../migration-2026-11-12.md)를 우선 확인한다.

## 왜 배우는가

원본 데이터 보존(S3)과 GPU 노드에서 빠른 반복 읽기(EBS/로컬 캐시)는 다른 요구사항이다.

## 선행 개념·내부 동작

S3 데이터셋→IAM·네트워크→로컬 EBS 복사/캐시→YOLO 파일 로더→GPU.

## 실제 운영 맥락·작업 예시

이미지 객체 다수의 개별 요청과 아카이브 묶음 다운로드는 요청량·지연·코드가 달라진다.

## 실습 준비 (GPU 비용 발생 여부)

- 실행 환경: **L+G1**. `L`은 로컬/이론, `G1`은 단일 GPU EC2, `G2`는 EKS GPU Worker 2대, `O`는 오프라인 기록·분석을 의미한다.
- G1/G2는 **AWS 계정 GPU 쿼터 승인·AZ 용량 확인 후**, 인스턴스·EKS·EBS·NAT 등의 비용 및 자원 삭제 계획을 검토한 다음에만 수행한다.
- 사용할 AMI·컨테이너 이미지·CUDA·YOLO·데이터셋의 버전, GPU 종류, Batch/Epoch, seed를 실제 실행 시 고정한다. 명령/출력은 실행 시점 실제 환경으로 검증한다.
- 관련 근거: [공식 자료 또는 실제 사례](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.html) (이 링크가 실제 장애의 발생을 증명하는 자료인지, 실험 또는 일반 가이드인지 유형을 구분한다).

## 직접 해볼 Lab

1. **사전 분석:** 예상 동작과 실패 가능 계층을 글과 경로도로 정리한다.
2. **구성·실행:** 이미지 객체 다수의 개별 요청과 아카이브 묶음 다운로드는 요청량·지연·코드가 달라진다.
3. **관측:** 로그, Kubernetes Events(해당 시), GPU/CPU/메모리/I/O, 시작·종료 시각, 모델/데이터 버전을 수집한다.
4. **대조·검증:** 같은 입력과 GPU 조건의 정상 기준선과 비교하고, 기대와 다른 관측이 나오면 원인 가설·반증 조건을 기록한다.
5. **운영 정리:** 필요한 파일은 별도 저장소에 보존한 뒤 GPU/EKS/네트워크 잔여 요금 리소스를 확인한다.

## 완료 증거

스토리지 경로 도식, 실제 다운로드 시간·전송량·캐시 조건; 선택·제외 근거.

실제 GPU가 필요한 내용은 GPU 없이 완료 처리하지 않는다. 가상 사례·기대 출력은 **실측이 아님**을 표시한다.
