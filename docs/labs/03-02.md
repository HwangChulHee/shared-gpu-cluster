# Lab 03-02 — YOLO DataLoader·CPU 전처리 (기초)

> 새 21 Lab · 실측 전 · 환경: **G1** · GPU 승인/비용 게이트 필수.
>
> **범위 구분:** 이 Lab은 DataLoader의 동작 원리와 정상 처리 기준선 확보에 집중합니다. 실제 저장소/워커 설정을 바꿔 **개선 전후 대조 실험**하는 것은 [06-02](../labs/06-02.md)에서 한 번 수행합니다.

## 왜 배우는가

YOLO 학습은 GPU 연산만으로 구성되지 않는다. 이미지 읽기와 디코딩, 리사이즈, 증강, Batch 구성은 CPU·메모리·스토리지에 영향을 받는다. GPU가 데이터를 기다린다면 GPU 사양을 높여도 속도가 개선되지 않을 수 있다.

## 내부 동작

`S3 데이터셋 → EBS/로컬 파일 → PyTorch/YOLO DataLoader → CPU decode/augment → batch/pinned memory(설정 시) → CPU→GPU 전송 → forward/backward`

- `workers=0`: 주 프로세스에서 로딩, 디버깅이 쉬우나 GPU가 대기할 가능성.
- `workers>0`: 별도 로더 프로세스로 데이터 준비를 병렬화할 수 있으나 CPU·RAM 사용과 프로세스 오버헤드가 커질 수 있음.
- `cache` 설정은 실행 조건과 메모리 사용을 바꾸므로 실험마다 명시한다.
- GPU Util은 표본화된 활동 시간 비율에 가까워 입력 병목을 단일 지표로 확정하지 못한다.

## 학습·실습

1. **비용 없는 단계:** YOLO 설정의 `workers`, `batch`, `imgsz`, `cache` 역할을 설명하고 GPU/CPU/I/O 중 어디에 영향을 주는지 예측한다.
2. **G1 사전 준비:** 쿼터 승인, GPU 사양·Driver·컨테이너·YOLO·데이터셋 버전, GPU 비용·삭제 계획 확인. 이미 [01-03](01-03.md)에서 검증한 실행 이미지와 데이터를 재사용.
3. **정상 기준선:** 짧은 YOLO 학습을 **하나의 고정된 DataLoader 설정**으로 수행. 데이터셋 파일 개수/전체 크기, CPU·RAM, GPU Util/VRAM, Epoch 시간, 데이터 준비시간을 기록한다.
4. **시간 경로 분석:** 로딩/전처리 시간과 GPU 계산을 가능하면 별도 계측. 동일 실행의 로그와 샘플링 한계를 기재한다.
5. **정리:** 입력 버전과 정상 기준선 결과를 보존하고 GPU 인스턴스 비용을 확인한다.

## 완료 증거

고정된 설정의 정상 학습 로그, 측정 시각/환경, GPU Util·CPU 사용률·처리시간, 전처리 단계와 GPU 연산 관계 설명. **개선 전후 실험은 06-02에서 검증**한다.

## 서술형 질문

GPU Util이 15%, CPU 사용률이 95%로 보일 때 DataLoader의 어느 단계에서 GPU가 기다리는지 어떻게 검증할까?
