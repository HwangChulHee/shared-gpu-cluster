# Lab 03-02 — 단일 Linux GPU 서버의 Prometheus·Grafana

> **2026-11-13 Linux GPU 서버 중심 교안** · 환경: **L+G1** · 실제 GPU 실험 미완료. [이관표](../migration-2026-11-13.md)에서 이전 번호를 확인한다.

## GPU 비용 최적화 실행 구간

> 공통 기준: [GPU 실행 게이트·G1/G2 런북](../gpu-execution-gates.md). **OFF 준비가 완료되어도 GPU 실측을 완료한 것은 아니다.** 실제 출력과 가설/계획을 구분한다.

| 구간 | 수행할 작업·완료 기준 |
|---|---|
| **GPU OFF-1 · 사전 학습/로컬 검증** | 로컬 Docker Compose로 node exporter→Prometheus→Grafana 실제 사용, scrape/PromQL/대시보드·메트릭 내보내기 검증; DCGM용 패널/연결 설계 |
| **GPU ON · 최소 시간 실측** | G1 DCGM exporter 연결, target UP 확인, 학습 구간 GPU+호스트 지표와 수집 오버헤드 측정 |
| **GPU OFF-2 · 분석/기록** | 원본/CSV/대시보드로 시계열 분석·보존; G1을 켜둔 채 Grafana 학습 금지 |

GPU가 필요한 실측은 각 세션에서 이미 준비된 명령·성공 기준·결과 저장 경로를 사용한다. 실패하면 원인 계층과 시간을 기록하고 사전 중단 조건을 적용한다.

## 실제 운영 요구와 학습 목적

EKS가 없어도 GPU/CPU/메모리·디스크의 지표 수집·시각화를 구축할 수 있다. GPU 서버 관측 체계를 먼저 이해하고 뒤에서 K8s 지표를 추가한다.

## 내부 동작·책임 분리

`GPU DCGM exporter + Linux node exporter → Prometheus scrape → Grafana dashboards`

## 학습 및 직접 실습

1. 모니터링 항목(GPU 사용률/VRAM, CPU/RAM/디스크, 노드 프로세스)과 exporter/Prometheus/Grafana 역할 설명.
2. 비용 없이 L에서 Docker Compose 등으로 Prometheus/Grafana 설정과 대시보드·스크레이프 구성을 준비하고 보안/포트·인증 점검.
3. G1에서 Driver/Toolkit과 exporter의 호환성을 확인한 후 NVIDIA DCGM exporter 및 node exporter 실행. **g6.xlarge의 16GiB 호스트 RAM을 고려해 모니터링 컨테이너가 YOLO 학습에 주는 CPU/RAM 영향을 관측**한다. 필요하면 관측용 Prometheus/Grafana는 다른 저비용 환경으로 분리할 수 있지만 비용 증가를 기록한다. 실제 `/metrics` 노출·Prometheus target UP 확인.
4. YOLO 실행 중의 호스트 CPU·디스크 지표와 GPU 지표를 동일 시간 범위에서 시각화. 단순한 GPU Util과 실제 학습시간을 함께 기록.
5. Grafana 설정·메트릭 증거 외부 보존 및 CPU·메모리 사용 오버헤드/비용 확인. **kube-state-metrics는 이 단계에 설치하지 않음**.

## 완료 판정에 필요한 실제 증거

G1 Prometheus target 상태, Grafana 대시보드/실제 PromQL·메트릭, YOLO·GPU·호스트 지표 시간축.

GPU/EKS 실행 전 **G/VT 쿼터 8 vCPU 적용 확인**과 별도로 EC2 AZ 용량·AMI·실제 가격·EBS/S3/NAT/IPv4 부대 비용·리소스 삭제 계획을 검토한다. 준비되지 않으면 L 이론만 진행하고 GPU 실습은 **대기**로 표시한다. 예상과 실제 출력은 구분한다.
