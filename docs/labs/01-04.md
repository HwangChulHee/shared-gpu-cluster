# Lab 01-04 — Gemma 4 추론

> **학습 교안 / 실행 전**. 예시와 예상 동작은 실측 결과가 아닙니다. 학습 시작 시 [진도표](../../learning/progress.md)에서 상태 확인.

## 왜 배우는가

챗봇 서비스는 모델 적재와 토큰 생성이 발생하는 GPU 추론 환경을 실제로 경험하기 위한 워크로드다.

## 핵심 개념

1. LLM 추론은 토큰을 순차적으로 생성한다. 모델의 첫 로딩·프롬프트 처리 단계와 토큰 생성 단계의 자원 사용 특성이 다를 수 있다.

2. 양자화는 모델 가중치의 저장 정밀도를 낮춰 메모리 요구를 줄인다. 대신 런타임 호환성, 품질, 성능 차이가 생길 수 있다. KV 캐시 용량은 문맥 길이·동시성에 영향을 받는다.

3. 모델 파일 저장(S3/디스크), CPU RAM 적재, GPU VRAM 적재는 다른 단계다. 다운로드가 느린 문제와 GPU 메모리 부족을 혼동하지 않는다.

## 내부 동작 흐름

모델 아티팩트 다운로드/캐시 → 런타임 시작 및 VRAM 적재 → 입력 토큰화 → 프롬프트 처리 → 토큰 생성 → 응답/로그 저장.

## 실무·프로젝트 예시

한 사용자만 채팅할 때는 되지만 여러 사용자가 긴 질문을 던지면 KV 캐시나 추론 엔진 설정으로 지연 또는 메모리 문제가 발생할 수 있다.

## 실습 전 준비

선택한 Gemma 4 가중치 사용 조건·접근 권한, 지원 추론 런타임, 양자화 형식 및 GPU 메모리 적합성 확인. 모델·런타임 버전과 프롬프트 고정.

## 직접 해볼 실습

1. G1에서 한 프롬프트로 짧은 배치 추론을 수행하고 결과·실행시간 기록.
2. 모델 초기 적재 시간과 워밍업 후 추론 지연을 구분해 기록.
3. `nvidia-smi`/NVML로 추론 중 VRAM과 사용률 관찰. 가능하면 문맥 길이 또는 동시 요청 수를 변경해 차이 확인.

**주의:** G1 실습은 EC2 가동시간·쿼터·사용 리전을 먼저 확인하고, 결과 보존 후 인스턴스를 정리합니다. 세부 명령·컨테이너 태그는 실습 시점의 실제 AMI 및 버전에 맞춰 고정합니다.

## 검증 및 산출물

- 실제 GPU 추론과 모델 버전의 증거 보존
- 시연용 모델의 VRAM 상한 및 제한 설명 가능

## 서술형 인출 질문 (학습 후 답변)

1. LLM 실행 시작 시 느린 이유와 응답 생성 도중 느린 이유는 어떻게 구분하는가?
2. 양자화하면 모델 파일은 작아지는데 왜 VRAM 문제가 여전히 발생할 수 있는가?
