# Lab 02-04 — IaC 수명주기와 최소 영속 저장

> **ARCHIVED — 이전 29 Lab 교안 / 현재 21 Lab 필수 목록에서 제외**. 이 문서는 이전 주제 「IaC 운영·수명주기 (구 과정)」의 학습 이력 보존용입니다. [현행 21 Lab](README.md) · [이관표](../migration-2026-11-12.md). 아래 내용은 현재 프로젝트의 필수 구현 사항이 아닙니다.


> **학습 교안 / 미실행**. 실행 절차는 실제 AWS/패키지 버전에 맞춰 고정한 뒤 수행합니다. 예상 결과는 실측 결과가 아닙니다.

## 학습 맥락과 목표

YOLO가 worker의 임시 경로에 체크포인트를 저장한 뒤 EC2가 중단되면 새로운 노드에서 학습을 재개할 파일이 없을 수 있다. S3에 성공적으로 올렸는지 먼저 검증한다.

## 핵심 개념·원리

1. Terraform state는 실제 AWS 리소스 ID와 설정 관계를 기억한다. 코드가 같아도 state가 없거나 외부에서 수동 변경했다면 plan 결과가 달라질 수 있다.

2. Kubernetes 애드온·Manifest는 Terraform 인프라와 구분해 순서대로 배포해야 한다. EKS가 생성되었다고 Device Plugin이나 사용자 Job이 자동 설치되는 것은 아니다.

3. 노드 로컬 파일은 노드 종료 시 보존되지 않을 수 있다. 기본 학습 결과와 체크포인트를 S3로 내보내는 최소 영속 경로를 Phase 02부터 마련해야 이후 사용자 API와 장애 복구가 가능하다.

## 내부 흐름

Terraform apply → EKS/노드 Ready → GPU Plugin 및 워크로드 적용 → S3 결과/체크포인트 검증 → 로그·결과 확보 → Kubernetes 리소스 정리 → Terraform destroy → AWS 잔여 자원 점검.

## 실습 준비

S3 버킷 이름, 접근 권한/서비스 계정, 저장 기간 및 삭제 정책 설계. Terraform state와 비밀키는 공개 저장소에 커밋하지 않음.

## 실습

1. GPU Job에서 S3로 작은 결과 파일 업로드·재조회 검증. 노드 권한/Pod Identity 또는 IRSA 중 지원 환경 선택.
2. Terraform apply/destroy와 애드온 재적용 명령을 순서대로 문서화.
3. 인프라 제거 후 저장하기로 선택한 S3 결과는 남아 있는지 확인하고 보존 비용·삭제 정책 기록.

## 검증할 증거

- 다시 구축한 환경에서 동일 manifest 재실행
- 보존 결과와 삭제 대상 분리 확인, 잔여 과금 자원 점검

## 서술형 인출 질문

1. Terraform destroy가 성공했다고 모든 AWS 비용이 0원이 됐다고 말할 수 없는 이유는?
2. 노드 교체 후 체크포인트가 유실되었다면 어느 설계 원칙을 위반한 것인가?
