# Lab 05-01 — AI 데이터·스토리지 경로

> **사전 학습 교안 / 미실행**. 학습 도중 사용한 실제 버전·명령어·관측값은 별도의 학습 기록에 남깁니다.

## 학습 목표와 상황

S3에서 작은 파일 수천 개를 매 epoch 직접 읽는 설계와 캐시에 미리 내려받는 설계는 데이터 로딩 지연이 다를 수 있다. 단, 실제로 어떤 구성이 나은지는 측정해야 한다.

## 핵심 개념

1. S3는 객체 스토리지이며 EFS는 NFS 기반 공유 파일시스템이다. 파일 접근 방식과 성능 특성이 달라 동일한 경로처럼 사용할 수 없다.

2. 데이터셋과 모델 원본은 S3, 학습 중 공유 파일 접근은 필요 시 EFS/PVC, 반복 로드 최적화는 노드 로컬 캐시로 나눌 수 있다.

3. YOLO 체크포인트는 애플리케이션이 안전하게 저장하고 지속 저장소에 업로드해야 재시작 후 사용할 수 있다. S3 업로드 성공은 체크포인트 재개 성공과 구별한다.

## 내부 동작 경로

데이터셋 S3 원본 → 노드/Pod 다운로드 또는 EFS 마운트 → CPU 데이터 로딩 → GPU 연산 → 체크포인트/결과 → 지속 저장 → API 결과 조회.

## 실습 준비

Phase 02의 최소 S3 보존 경로, 데이터셋 파일 수·크기, 권한 및 EFS 생성/삭제 비용 확인.

## 직접 수행할 실습

1. 같은 데이터셋을 S3 다운로드 후 캐시 경로와 공유 파일시스템 후보에서 읽는 방식 비교.
2. YOLO 체크포인트 업로드 → 새로운 Pod에서 다운로드 → 이어 학습하는 절차 검증.
3. EFS CSI/PVC를 사용한다면 접근 방식과 RWX 필요성을 증명하고 실제 I/O 처리량·지연 수집.

## 검증·완료 기준

- 원본·캐시·체크포인트·결과를 다른 경로로 도식화
- 지속 저장소의 비용·접근권한·삭제 정책 기록

## 서술형 질문

1. S3 객체와 EFS 파일의 접근·일관성·성능 측면 차이는?
2. 체크포인트 파일을 S3에 보존했다는 사실만으로 학습 재개가 보장되지 않는 이유는?
