# Lab 05-02 — GPU Node Group 증감·운영

> **새 7 Phase / 21 Lab 교안, 미실측** · 환경: L+G2. 동일 번호를 사용한 이전 교안과 학습 기록은 [이관표](../migration-2026-11-13.md) 참조.

## GPU 비용 최적화 실행 구간

> 공통 기준: [GPU 실행 게이트·G1/G2 런북](../gpu-execution-gates.md). **OFF 준비를 GPU 실측 완료로 간주하지 않는다.**

| 구간 | 수행할 작업·완료 기준 |
|---|---|
| **GPU OFF-1 · 사전 학습/로컬 검증** | GPU 8 vCPU 쿼터와 Node Group 1↔2 증감·drain/복구 영향, 변경 스크립트·종료 기준 사전 정의 |
| **GPU ON · 최소 시간 실측** | G2 노드 수 변경과 GPU Capacity/Job 배치 지연 실제 확인 |
| **GPU OFF-2 · 분석/기록** | 노드/Job 복구시간·증설 비용 분석 |

GPU가 필요한 실측은 사전에 준비한 명령·성공 기준·보존 경로에 따라 실행한다. 실패하면 진단 시간·비용 상한을 적용하고 후속 실험을 멈춘다.

## 학습 목표·왜 필요한가

GPU 노드 증감에는 노드 준비, 드라이버 등록, 작업 배치 및 비용이 따른다.

## 내부 동작·구성 요소

노드 그룹 용량 변경→EC2→Node Ready→GPU 등록→Pod.

## 실무 시나리오

노드 수를 조절한 후 자원 가용량과 작업 시작 지연을 관측한다. **2×g6.xlarge가 GPU 쿼터 8 vCPU 전체를 사용하는 만큼 Scale-up은 최대 2대까지만 가능하며, Scale-down 전에 실행 중 Job의 종료/중단 영향과 PDB·드레인 동작을 확인**한다.

## GPU 8 vCPU 쿼터 내 노드 운영 계약

- `g6.xlarge`는 4 vCPU이므로 **GPU Worker 2대가 승인된 G/VT 8 vCPU 쿼터를 모두 점유**한다. 노드가 Ready인지와 별개로 **기존 EC2 인스턴스가 실제로 종료되어 쿼터가 반환됐는지** 확인하기 전에는 세 번째 GPU 노드가 생긴다고 가정하지 않는다.
- 정상 실험은 **1대 → 2대** 증설, 이후 다른 GPU 작업/결과가 보존됐음을 확인한 뒤 **2대 → 1대** 축소로 설계한다. 축소 중 실행 중인 GPU Job의 중단 가능성을 기록하고 종료·재시도 방식을 따로 계획한다.
- Node Group desired/min/max, EC2 가동 수, Node Ready, `nvidia.com/gpu` Allocatable, Pod Pending/Running과 시간·비용을 구분해 수집한다. 관리형 노드그룹/ASG 교체가 예기치 않은 추가 용량을 시도할 수 있으므로 **업데이트·서지·교체 설정**을 미리 검토한다.
- 부족한 쿼터/Capacity 상황의 대안은 GPU Worker 축소 또는 쿼터 조정 후 별도 세션. 실패한 Scale-up을 무한 재시도하지 않는다.

## 준비·실습 (실제 사용자가 실행)

1. **사전 분석:** 위 시나리오의 운영 요구사항과 예상 실패 계층을 서술한다.
2. **비용 게이트:** 환경 L+G2. G1/G2가 포함될 경우 먼저 AWS GPU 쿼터 승인, EC2/EKS/네트워크/스토리지 비용, 생성·삭제 경로를 확인한다. 쿼터 8 vCPU는 승인·적용 확인됐지만 실제 AZ 용량·비용·AMI 준비 전에는 GPU를 실행하지 않는다.
3. **실행 준비:** AMI/Driver/CUDA/컨테이너, YOLO·데이터셋, Batch/Epoch, seed, 캐시 상태를 고정한다. 실행 명령은 실제 버전과 환경을 확인한 뒤 단계별로 확정한다.
4. **실행:** 노드 수를 조절한 후 자원 가용량과 작업 시작 지연을 관측한다.
5. **관측·분석:** 정상 기준선을 먼저 기록한 뒤 GPU·CPU·RAM·스토리지·Pod/Job Events 중 관련 지표를 수집한다. 대조군, 예상/실측, 반증 조건, 통제된 실패 주입 여부를 구분한다.
6. **정리:** 결과/Checkpoint 보존, Terraform/EC2/EKS/NAT/EBS/S3 잔여 과금 자원 점검.

## 완료 증거

EC2/노드/GPU 수·준비시간·비용/쿼터 기록.

실측이 없다면 계획 단계로 남긴다. [실제 사례·공식 근거](https://docs.aws.amazon.com/eks/latest/userguide/managed-node-groups.html)는 출처 유형을 분리해서 기록하며, 장애 주입을 자연 발생 장애처럼 표현하지 않는다.
