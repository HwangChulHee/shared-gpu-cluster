## GPU 비용 최적화 실행 구간

> 공통 기준: [GPU 실행 게이트·G1/G2 런북](../gpu-execution-gates.md). **OFF 준비가 완료되어도 GPU 실측을 완료한 것은 아니다.** 실제 출력과 가설/계획을 구분한다.

| 구간 | 수행할 작업·완료 기준 |
|---|---|
| **GPU OFF-1 · 사전 학습/로컬 검증** | COCO8 smoke와 별도 benchmark 데이터셋 확정; 시간 계측/반복·캐시/배치·seed/스크립트/로그 서식 사전 검증 |
| **GPU ON · 최소 시간 실측** | G1 동일 환경 baseline 측정, 3회 반복 지향; 실패 시 이후 튜닝 시험 중단 |
| **GPU OFF-2 · 분석/기록** | 로컬에서 평균·편차·병목 가설 비교; 06-02 대조군으로 재사용 |

GPU가 필요한 실측은 각 세션에서 이미 준비된 명령·성공 기준·결과 저장 경로를 사용한다. 실패하면 원인 계층과 시간을 기록하고 사전 중단 조건을 적용한다.

## 실제 운영 요구와 학습 목적

학습 완료시간은 GPU 연산 외에도 이미지 준비·CPU 작업·Checkpoint·파일 복사로 결정된다. 측정 구간을 정의해야 개선 결과가 의미 있다.

## 내부 동작·책임 분리

`데이터 준비 → 배치 읽기/CPU 변환 → H2D/GPU 연산 → 동기화/최적화 → Checkpoint/결과 저장`

## 정상 기준선 실험 계약 — GPU OFF-1에 확정

| 항목 | 사전 결정/판정 방법 |
|---|---|
| 입력 | COCO8은 **Smoke Test 전용**; Benchmark는 별도의 공개·라이선스 확인 데이터셋. 이미지 수/총 크기·클래스·압축 여부·해시 및 S3/EBS 경로를 기록 |
| 동일 조건 | GPU/AMI/Driver/CUDA/이미지 digest, YOLO 모델·데이터, `imgsz`·`batch`·`epochs`·`workers`·`cache`·`seed`·스토리지 경로를 기준선에서 고정 |
| 시간 구간 | S3 다운로드, 프로세스 초기화, 학습 epoch, Checkpoint 저장, 결과 업로드를 분리. GPU 비동기 연산 시간을 별도 계측할 때 동기화 위치도 정의 |
| 반복·캐시 | 기준선 3회 반복 지향(예산상 축소 기록). cold/warm cache, 첫 Epoch 오버헤드와 샘플 개수를 구분; OS 페이지 캐시를 임의로 비우는 위험한 명령은 기본 실험에서 사용하지 않음 |
| 측정 | wall-clock 시간·이미지 처리량(images/s)·epoch 시간, GPU Util/VRAM, CPU·RAM·디스크 I/O, 로그/메트릭 수집 간격·누락 여부 |
| 합격 | 계층별 CUDA/YOLO 정상, 모든 반복의 동일 설정 증거, 지표/로그 저장, Run ID와 S3 증거 존재 확인. 계측 실패 시 06-02로 넘어가지 않음 |

GPU OFF-1에서 위 항목을 **실제 값으로 채운 실행 조건표**와 파라미터별 스크립트를 준비한다. 위 표는 사전 계약 템플릿이며 GPU 실측값이나 최종 데이터셋 선정 결과가 아니다.

## GPU OFF-1 데이터셋 구성 실행 절차 (2026-11-19 추가)

- 재현 가능한 YOLO 벤치마크 데이터 준비: [`scripts/prepare-coco-benchmark.py`](../../scripts/prepare-coco-benchmark.py)
- 출처: COCO 2017 `val2017.zip` 및 `annotations_trainval2017.zip`의 `instances_val2017.json`. 이미지 5,000장 중 seed=42로 1,000장 선정, 900장은 `images/train`, 100장은 `images/val`로 구분. COCO category ID → 연속된 YOLO class ID 변환; bounding box는 좌표 정규화하여 `labels/{train,val}`에 저장.
- **주의:** 원래 COCO *validation* 이미지에서 벤치마크용 train/val을 추출하므로 **모델 품질·일반화 평가의 독립 검증 데이터로 해석할 수 없다.** 이 Lab에서는 인프라 처리량·학습 시간 검증 전용으로 사용.
- 선정 이미지의 SHA256, 원본 두 ZIP의 SHA256, seed·split·image ID를 `manifest.json`에 저장. 데이터 및 ZIP은 Git 제외(`datasets/`); S3에는 출력 데이터셋을 아카이브하여 보존. 실제 S3 업로드/데이터 해시는 사용자 실행으로 확인될 때만 기록.
- 기본 1,000장 실험 데이터의 정확한 압축 후 용량은 내려받아 측정. **원본 ZIP 다운로드가 큰 편**이므로 GPU OFF-1 로컬에서만 수행.
- 실제 COCO 다운로드/변환/YOLO smoke/G1 실행은 **아직 미실행**. 작은 가상 JSON/ZIP 4장으로 스크립트의 추출·YOLO 라벨·체크섬 생성 기능을 제작 환경에서 확인했으나 실제 COCO 내용 검증과는 구분.

로컬에서:
```bash
mkdir -p datasets/coco-source
curl -fL --retry 3 -o datasets/coco-source/val2017.zip 'https://images.cocodataset.org/zips/val2017.zip'
curl -fL --retry 3 -o datasets/coco-source/annotations_trainval2017.zip 'https://images.cocodataset.org/annotations/annotations_trainval2017.zip'
python3 scripts/prepare-coco-benchmark.py \
  --images-zip datasets/coco-source/val2017.zip \
  --annotations-zip datasets/coco-source/annotations_trainval2017.zip \
  --count 1000 --val-count 100 --seed 42
find datasets/coco2017-benchmark/images/train -type f | wc -l
find datasets/coco2017-benchmark/images/val -type f | wc -l
```

`data.yaml`에 dataset root를 별도 고정하지 않아 아카이브 이동 시에도 상대 구조를 유지한다. 실제 Ultralytics dataset load 성공 여부는 이후 검증해야 한다.

참고: [공식 COCO dataset](https://cocodataset.org/#download), [Ultralytics detection dataset format](https://docs.ultralytics.com/datasets/detect/).

## GPU OFF-1 YOLO 기준선 실행 스크립트

[`scripts/run-yolo-benchmark.py`](../../scripts/run-yolo-benchmark.py) — 초기 기준선: YOLO11n, 이미지 640, batch 8, workers 2, epochs 3, seed 42, cache false, NVIDIA CUDA device 0.

로컬에서는 아래 명령으로 데이터셋 존재 여부·split·JSON manifest·라벨/이미지 경로·학습 설정을 검증한다. `--dry-run`은 Ultralytics 실행 및 GPU 접근을 하지 않는다.

```bash
python3 scripts/run-yolo-benchmark.py --dry-run
python3 -m py_compile scripts/run-yolo-benchmark.py
```

G1에서는 준비한 GPU Python 환경 및 사전 다운로드한 `yolo11n.pt`(버전/해시 확보)를 사용하여:

```bash
python3 scripts/run-yolo-benchmark.py --repeat 1
# baseline 성공 및 예산/시간 확인 후에만 --repeat 3 고려
```

출력: `artifacts/benchmark/baseline-01/training.log`, `summary.json`, `train/results.csv` (Ultralytics가 정상 출력하는 경우). `summary.json`의 images/sec는 **900 × epochs / 전체 실행시간**의 end-to-end 평균 추정치이므로 epoch 또는 GPU-only 처리량과 혼동 금지. YOLO 실제 데이터로더 Worker 수는 로그 확인. 첫 실행의 모델 가중치 다운로드·CUDA 초기화 등이 결과에 영향을 줄 수 있으므로 가중치 사전 다운로드/고정, cold/warm 구분 필요.

G1 실행 및 스크립트 실제 데이터 검증은 아직 확인되지 않았으며, GPU 벤치마크 성공으로 기록하지 않는다.

## 학습 및 직접 실습

1. YOLO 모델·데이터 버전, batch/epoch/imgsz/workers/cache, GPU/AMI/CPU/RAM, GPU 측정 간격을 고정.
2. 입력 다운로드·학습 초기화·epoch·Checkpoint 저장·결과 업로드 구간의 시작/종료 시간을 정의.
3. 03-01/03-02의 GPU/호스트 메트릭과 학습 로그를 같은 시간축으로 관측. 콜드/웜 캐시 구분.
4. 예산 내에서 3회 반복을 목표로 평균·편차·결측 지표 기록. 실제 CPU 병목 또는 I/O 병목 여부는 관측값이 지원할 때만 주장.
5. 이 기준선을 **06-02의 튜닝 실험 대조군**으로 재사용하여 불필요한 동일 실험 중복 방지.
