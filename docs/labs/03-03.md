# Lab 03-03 — 단일 GPU 학습 성능 기준선·병목 해석

> **2026-11-13 Linux GPU 서버 중심 교안** · 환경: **G1/O** · 실제 GPU 실험 미완료. [이관표](../migration-2026-11-13.md)에서 이전 번호를 확인한다.

## 실제 운영 요구와 학습 목적

학습 완료시간은 GPU 연산 외에도 이미지 준비·CPU 작업·Checkpoint·파일 복사로 결정된다. 측정 구간을 정의해야 개선 결과가 의미 있다.

## 내부 동작·책임 분리

`데이터 준비 → 배치 읽기/CPU 변환 → H2D/GPU 연산 → 동기화/최적화 → Checkpoint/결과 저장`

## 학습 및 직접 실습

1. YOLO 모델·데이터 버전, batch/epoch/imgsz/workers/cache, GPU/AMI/CPU/RAM, GPU 측정 간격을 고정.
2. 입력 다운로드·학습 초기화·epoch·Checkpoint 저장·결과 업로드 구간의 시작/종료 시간을 정의.
3. 03-01/03-02의 GPU/호스트 메트릭과 학습 로그를 같은 시간축으로 관측. 콜드/웜 캐시 구분.
4. 예산 내에서 3회 반복을 목표로 평균·편차·결측 지표 기록. 실제 CPU 병목 또는 I/O 병목 여부는 관측값이 지원할 때만 주장.
5. 이 기준선을 **06-02의 튜닝 실험 대조군**으로 재사용하여 불필요한 동일 실험 중복 방지.

## 완료 판정에 필요한 실제 증거

조건표, 단계별 실측 소요시간과 지표, 정상 기준선·반증 조건·반복/한계 문서.

GPU/EKS 실행 전 **G/VT 쿼터 8 vCPU 적용 확인**과 별도로 EC2 AZ 용량·AMI·실제 가격·EBS/S3/NAT/IPv4 부대 비용·리소스 삭제 계획을 검토한다. 준비되지 않으면 L 이론만 진행하고 GPU 실습은 **대기**로 표시한다. 예상과 실제 출력은 구분한다.
