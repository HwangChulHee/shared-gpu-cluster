# Lab 04-02 — Terraform EKS·GPU Worker 구축

> **2026-11-13 개편 · GPU Linux 서버에서 EKS로 확장** · 환경: L+G2. **실제 EKS GPU 실습 미수행**. [Lab 이관](../migration-2026-11-13.md) 및 [운영 비용 게이트](../operations.md) 참조.

## GPU 비용 최적화 실행 구간

> 공통 기준: [GPU 실행 게이트·G1/G2 런북](../gpu-execution-gates.md). **OFF 준비를 GPU 실측 완료로 간주하지 않는다.**

| 구간 | 수행할 작업·완료 기준 |
|---|---|
| **GPU OFF-1 · 사전 학습/로컬 검증** | EKS Terraform fmt/validate/plan, CPU/GPU 노드·Control Plane·NAT 예산과 destroy 경로, AMI/Plugin 호환성·state 전략 확정 |
| **GPU ON · 최소 시간 실측** | G2 apply→Node Ready·GPU Worker 2대 확인 및 버전·비용·삭제 증거 수집 |
| **GPU OFF-2 · 분석/기록** | 실제 구성·예상 비용·생성/삭제 로그 비교 |

GPU가 필요한 실측은 사전에 준비한 명령·성공 기준·보존 경로에 따라 실행한다. 실패하면 진단 시간·비용 상한을 적용하고 후속 실험을 멈춘다.

## 운영 요구사항

G1에서 검증한 컨테이너와 데이터를 EKS에서 운영하려면 GPU Worker와 CPU 시스템 노드, AMI/Driver/Toolkit의 책임을 분리해야 한다.

## 내부 동작

`Terraform VPC/IAM → EKS control plane → CPU nodegroup → GPU nodegroup 2 nodes → Node Ready → NVIDIA runtime`

## 학습·실습 순서

1. EKS 제어면과 CPU 시스템 노드/서로 다른 GPU Worker 두 대의 역할, CPU/MEM/GPU 용량 요구사항 설명.
2. Terraform 모듈·버전 고정, state 위치·생성/삭제 순서, AWS G/VT 8 vCPU에서 g6.xlarge 2대가 쿼터상 맞는지 확인.
3. G2를 만들기 전에 전체 AWS 비용(EKS Control Plane, CPU/ GPU 노드, EBS·NAT·IPv4 등) 견적과 실험 종료 시점을 확인.
4. `terraform apply` 후 EC2/Node 이름·AZ·AMI·`kubectl get nodes -o wide`와 노드 상태를 실제로 확인.
5. **AMI별 NVIDIA 구성 확인:** EKS AL2023 NVIDIA AMI는 Driver/Container Toolkit이 포함되어 있으나 NVIDIA Device Plugin은 별도 구성. EKS Bottlerocket NVIDIA AMI는 Device Plugin까지 포함됨. 사용할 AMI를 먼저 고정하고 GPU Operator의 Driver/Toolkit/Plugin 중복 설치를 방지한다. 실험 후 로그 보존·리소스 제거.

## 완료 증거

실제 EKS/EC2/CPU/GPU 노드 목록·버전·생성·삭제/비용 근거.

실제 실행 전에는 결과·복구·사용률을 만들어내지 않는다. AWS GPU 8 vCPU 쿼터는 승인됐지만 AZ 용량과 실제 실행 비용·동작은 별도 검증이 필요하다.
