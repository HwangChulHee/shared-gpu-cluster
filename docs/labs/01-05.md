# Lab 01-05 — YOLO 이미지 학습

> **학습 교안 / 실행 전**. 예시와 예상 동작은 실측 결과가 아닙니다. 학습 시작 시 [진도표](../../learning/progress.md)에서 상태 확인.

## 왜 배우는가

YOLO는 배치 학습, 체크포인트와 장애 복구를 검증하기 쉬운 GPU 워크로드다.

## 핵심 개념

1. Epoch은 학습 데이터셋 전체를 한 번 사용하는 주기, batch size는 한 번에 학습하는 샘플 수다. Batch size 증가는 처리량을 높일 수 있지만 VRAM 요구량도 커질 수 있다.

2. 학습 도중 저장되는 checkpoint는 단순 모델 가중치와 다를 수 있다. 학습을 정확히 재개하려면 optimizer state, epoch, scheduler 등 프레임워크가 지원하는 정보를 확인해야 한다.

3. 이미지 디코딩, 증강, 로더 워커 등의 CPU 측 전처리가 느리면 GPU는 계산 대기 상태가 될 수 있다.

## 내부 동작 흐름

이미지/라벨 읽기 → CPU 전처리·증강 → GPU 전송 → Forward → Loss → Backward/Optimizer → checkpoint/결과 저장.

## 실무·프로젝트 예시

GPU Worker가 중단되었을 때 마지막 가중치 파일은 복구돼도 데이터셋 위치와 이전 optimizer state가 없다면 원래 학습 위치로 정확히 돌아가지 못할 수 있다.

## 실습 전 준비

소형 YOLO 모델 및 공개·합성 데이터셋 선정, 라이선스·라벨 포맷 검증. epoch과 batch를 작게 시작.

## 직접 해볼 실습

1. G1에서 짧은 학습을 실행하고 epoch별 로그·학습 시간 기록.
2. 체크포인트와 예측 이미지 등 결과가 생성되었는지 확인.
3. 정상 종료 후 지원되는 재개(resume) 방식으로 작은 추가 학습을 실행해 이전 상태 활용 여부 확인.

**주의:** G1 실습은 EC2 가동시간·쿼터·사용 리전을 먼저 확인하고, 결과 보존 후 인스턴스를 정리합니다. 세부 명령·컨테이너 태그는 실습 시점의 실제 AMI 및 버전에 맞춰 고정합니다.
