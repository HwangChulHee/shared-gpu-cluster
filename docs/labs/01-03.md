# Lab 01-03 — GPU 소프트웨어 스택

> **학습 교안 / 실행 전**. 예시와 예상 동작은 실측 결과가 아닙니다. 학습 시작 시 [진도표](../../learning/progress.md)에서 상태 확인.

## 왜 배우는가

호스트에서 GPU가 보이는 것과 Kubernetes Pod에서 GPU가 사용 가능한 것은 별도 문제다. 문제를 한 층씩 분리할 수 있어야 한다.

## 핵심 개념

1. NVIDIA Driver는 운영체제와 물리 GPU 사이의 핵심 계층이다. CUDA Toolkit/Runtime과 프레임워크는 GPU 계산을 요청한다. NVML은 장치 상태를 관찰하는 API이며 `nvidia-smi`는 이를 활용하는 대표 도구다.

2. NVIDIA Container Toolkit은 컨테이너 런타임과 GPU 장치/라이브러리의 노출을 연결한다. 호스트 `nvidia-smi`가 성공하더라도 컨테이너 안에서 GPU가 보이지 않을 수 있다.

3. EC2 단일 GPU 검증에는 Kubernetes Device Plugin이 필요하지 않다. Device Plugin은 Phase 02에서 kubelet에 확장 자원인 `nvidia.com/gpu`를 알리기 위해 사용한다.

## 내부 동작 흐름

호스트 OS → NVIDIA Driver → GPU 장치; 컨테이너 실행 요청 → Container Runtime/Toolkit → 컨테이너에 장치·드라이버 라이브러리 연결 → CUDA 애플리케이션.

## 실무·프로젝트 예시

호스트에서 `nvidia-smi`가 성공하지만 GPU 컨테이너에서 실패하면 드라이버 고장으로 단정하지 말고 컨테이너 런타임 구성과 이미지·툴킷을 먼저 분리 확인한다.

## 실습 전 준비

GPU EC2 AMI 종류, NVIDIA Driver/Container Toolkit 버전 기록. Docker 설치 및 GPU 런타임 통합 방법은 선택한 AMI의 최신 지침을 따른다.

## 직접 해볼 실습

1. 호스트에서 `nvidia-smi`와 `nvidia-smi --query-gpu=name,memory.total,driver_version --format=csv` 수행.
2. GPU 컨테이너에서 `nvidia-smi` 실행. 이미지 태그는 선택한 드라이버 지원 범위에 맞춰 고정.
3. 호스트/컨테이너 각각의 GPU 가시성을 비교한 진단표 작성.

**주의:** G1 실습은 EC2 가동시간·쿼터·사용 리전을 먼저 확인하고, 결과 보존 후 인스턴스를 정리합니다. 세부 명령·컨테이너 태그는 실습 시점의 실제 AMI 및 버전에 맞춰 고정합니다.

## 검증 및 산출물

- 호스트 및 컨테이너 실행 출력과 설치 버전 보존
- 확인 후 인스턴스를 종료하거나 제거하고 요금 확인

## 서술형 인출 질문 (학습 후 답변)

1. 호스트에선 GPU가 보이지만 컨테이너에는 보이지 않을 때 어떤 계층부터 확인하겠는가?
2. NVML, CUDA Runtime, Device Plugin의 역할은 어떻게 다른가?

## 실습 확장: 정상 출력과 오류의 구분

**실행 위치: 단일 NVIDIA GPU EC2 호스트(G1).** 인스턴스 종류, AMI/OS, 드라이버 버전을 먼저 기록한다.

```bash
nvidia-smi
nvidia-smi --query-gpu=name,driver_version,memory.total --format=csv
docker info --format '{{json .Runtimes}}'
```

- 첫 두 명령은 **호스트 GPU 드라이버·장치 인식**을 확인한다. 세 번째는 Docker 런타임 설정 관찰일 뿐, 출력에 NVIDIA 문자열이 있다는 사실만으로 GPU 컨테이너 실행 성공을 보장하지 않는다.
- **컨테이너 측 검증(예시):** 선택한 CUDA 이미지/호스트 드라이버와 호환되는 이미지 태그를 먼저 확인한 뒤 `docker run --rm --gpus all <검증된-CUDA-이미지> nvidia-smi`를 실행한다. `<...>`는 실제 태그로 교체해야 하며 그대로 실행하는 명령이 아니다.
- **기대 결과(실측 아님):** 호스트와 컨테이너에서 GPU 모델이 보인다. 오류가 나면 먼저 호스트 `nvidia-smi` 성공 여부로 분기한다. 호스트 실패 → 드라이버·장치/AMI, 호스트 성공·컨테이너 실패 → Toolkit/Docker 런타임·이미지 호환성 점검.
- EKS의 `nvidia.com/gpu` 검증은 [Lab 02-03](02-03.md)에서 한다. 단일 EC2 호스트 Docker 실습에 Device Plugin을 설치하지 않는다.
