# Lab 04-04 — API 권한과 부서 격리

> **사전 학습 교안 / 미실행**. 학습 도중 사용한 실제 버전·명령어·관측값은 별도의 학습 기록에 남깁니다.

## 학습 목표와 상황

Team A의 Job ID를 알아낸 Team B가 결과 API를 호출했을 때 데이터 유출이 발생하지 않아야 한다. URL 자체를 숨기는 것은 보안 경계가 아니다.

## 핵심 개념

1. 브라우저에서 팀 탭을 누르는 것은 인증이 아니다. 서버가 신뢰할 수 있는 사용자 정보로 팀 권한을 검사해야 한다.

2. Kubernetes ServiceAccount의 RBAC 권한은 API 서버가 허용할 수 있는 작업 범위를 제한한다. 애플리케이션이 사용자 요청을 검증하는 로직도 별도로 필요하다.

3. 임의 컨테이너 이미지, 커맨드, 마운트와 환경변수를 사용자가 직접 지정하게 하면 GPU 서비스가 임의 코드 실행 통로가 될 수 있다.

## 내부 동작 경로

사용자 인증/데모 신원 정책 → FastAPI 서버 팀 권한 검사 → 허용된 모델/Job 파라미터만 사용 → 권한 제한된 ServiceAccount로 K8s 호출.

## 실습 준비

시연용 인증 수준 명시. 실제 외부 공개 서비스가 아닌 폐쇄된 데모라면 그 한계를 README에 기록.

## 직접 수행할 실습

1. 팀별 Job 조회/결과 API에 서버 측 권한 검사.
2. 허용되지 않은 다른 팀 Job ID로 조회한 요청을 거부.
3. K8s RBAC로 Job 생성·조회 범위를 좁히고 `kubectl auth can-i` 등의 검증 수행.

## 검증·완료 기준

- 정상·거절(403/404 정책) 사례와 증거 기록
- 임의 이미지·명령/과도한 epoch 등 위험 입력 거부

## 서술형 질문

2. 브라우저에서 입력을 검증해도 FastAPI의 서버 측 검증이 필요한 이유는?
