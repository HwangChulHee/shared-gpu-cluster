# Lab 01-06 — XGBoost GPU 데이터 분석

> **학습 교안 / 실행 전**. 예시와 예상 동작은 실측 결과가 아닙니다. 학습 시작 시 [진도표](../../learning/progress.md)에서 상태 확인.

## 왜 배우는가

GPU를 사용하는 머신러닝 작업이라고 모두 딥러닝인 것은 아니다. 정형 데이터 배치 분석은 실행 시간이 짧아 큐 실험에서 별도 특성을 가진다.

## 핵심 개념

1. XGBoost는 여러 결정 트리를 순차적으로 학습하는 그래디언트 부스팅 프레임워크다. GPU 구현에서는 히스토그램 방식의 트리 생성을 GPU로 가속할 수 있다.

2. `tree_method='hist'`, `device='cuda'`는 GPU 학습에 사용되는 대표 설정이다. 데이터가 너무 작으면 GPU 초기화/복사 비용 때문에 CPU보다 느릴 수 있다.

3. 실험 목적은 모델 정확도 최적화가 아니라 정형 데이터 배치 Job의 실행시간·GPU 점유·대기시간 측정이다.

## 내부 동작 흐름

CSV/테이블 입력 → 특징/레이블 준비 → DMatrix 또는 프레임워크 입력 → GPU hist 학습 → 예측·평가 → 결과 파일 저장.

## 실무·프로젝트 예시

XGBoost 작업이 수 초 만에 끝나면 3개 팀 경쟁 실험의 대기열을 보기 어렵다. 데이터 크기와 학습 반복을 조절해 수십 초 이상 점유하는 재현 가능한 구성을 마련한다.

## 실습 전 준비

공개·합성 테이블 데이터 준비, seed·데이터셋 버전·XGBoost 버전 고정.

## 직접 해볼 실습

1. 동일 데이터로 CPU 및 GPU 학습을 각각 실행하고 학습 시간·정확도 차이 기록.
2. GPU 학습 중 GPU 가시성과 메모리 사용량 확인.
3. 데이터량/학습 반복을 조절해 빠른 작업과 길게 점유하는 작업을 각각 구성.

**주의:** G1 실습은 EC2 가동시간·쿼터·사용 리전을 먼저 확인하고, 결과 보존 후 인스턴스를 정리합니다. 세부 명령·컨테이너 태그는 실습 시점의 실제 AMI 및 버전에 맞춰 고정합니다.

## 검증 및 산출물

- GPU 사용이 실제로 활성화되었음을 로그와 장치 메트릭으로 확인
- 동일 조건 반복을 위한 seed·버전·입력·시간 기록
