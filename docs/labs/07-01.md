# Lab 07-01 — 인프라 재현성과 비용

> **학습 교안 / 실행 전**. 아래 예시는 실제 테스트 결과가 아닙니다.

## 이 Lab을 배우는 이유

EKS는 삭제됐지만 NAT Gateway나 S3 객체가 남아 있다면 '완전 삭제'가 아니다. 반대로 보존하도록 설계한 결과 저장소는 잔여 비용으로 명시해야 한다.

## 핵심 개념과 내부 원리

1. IaC 재현성은 Terraform apply가 한 번 성공하는 것만이 아니다. 빈 환경에서 같은 리소스를 만들고, 애드온/워크로드를 같은 버전으로 적용하고, 검증·삭제를 반복할 수 있어야 한다.

2. Terraform은 외부 리소스 전체를 자동 관리하지 않을 수 있다. EKS 관리형/외부 서비스 리소스, 수동 생성 S3 객체, CloudWatch 로그와 잔여 ENI 등은 별도 확인한다.

3. 학습 자료와 측정 산출물을 보존하기 위해 일부 S3 리소스를 의도적으로 남긴다면 과금·수명주기·보안 정책을 명시해야 한다.

## 시스템 동작 흐름

깨끗한 환경 → Terraform init/plan/apply → EKS/노드 Ready → Add-on/Workload 배포 → 정상 테스트 → 실험 산출물 외부 저장 → destroy → 잔여 과금 감사.

## 실습 전 준비

현재 구성과 배포 버전/AMI pin, Terraform state 위치, AWS 세션 예산, 삭제/보존 대상 구분.

## 직접 실습

1. 신규 환경에서 문서에 적힌 순서만으로 구성·기본 테스트 재현.
2. EKS GPU/CPU 노드, Device Plugin, Kueue, DCGM, 앱/스토리지 연결 확인.
3. 인프라 제거 후 비용 발생 리소스를 점검하고 예상 비용과 실제 측정 가능 비용을 구분.

## 검증 기준과 남길 증거

- 단계별 커밋/로그·환경 버전으로 재현 가능성 증명
- 보존 저장소·클라우드 비용·삭제 증거 기록
