# Lab 07-02 — 사용자 시연 시나리오

> **학습 교안 / 실행 전**. 아래 예시는 실제 테스트 결과가 아닙니다.

## 이 Lab을 배우는 이유

데모에서 Gemma가 상시 GPU를 점유한 상태로 '세 개의 Job을 동시에 GPU 두 장에 넣었다'고 설명하면 실제 요구 GPU 수가 달라진다. 모드를 미리 표기한다.

## 핵심 개념과 내부 원리

1. 사용자 시연은 관리 대시보드에 Job 목록을 보여주는 것이 아니라 실제 Gemma 채팅·YOLO 학습·XGBoost 분석이 GPU 작업과 연결된 사실을 보여주는 것이다.

2. 시연 흐름은 부서 사용자 화면과 Grafana 두 관점을 연결한다. API의 상태 표시와 실제 GPU 사용량, Job 이벤트가 같은 시각에 변해야 한다.

3. GPU 두 개라는 물리적 제한 때문에 Gemma 상시 서비스 모드와 세 종료형 작업의 풀 공유 모드는 분리 시연한다.

## 시스템 동작 흐름

Gemma 실시간 채팅 시연 → YOLO 학습·결과 확인 → 종료형 Gemma/YOLO Job으로 2 GPU 점유 → XGBoost 대기 → GPU 반환/실행 → Grafana와 Job 이벤트 확인.

## 실습 전 준비

모델 캐시와 데이터셋, 화면/배포 버전, 예상 대기시간, 실패 시 대체 증거(실측 녹화/로그) 준비.

## 직접 실습

1. Gemma 질문/응답을 실제 GPU 서비스에서 보여준다.
2. YOLO 학습 요청·상태·결과 및 XGBoost 작업 완료 결과를 사용자 UI에서 확인.
3. 종료형 3개 Job을 2 GPU에 제출해 대기·반환을 시연하고 같은 시각 Grafana·Events 근거를 기록.

## 검증 기준과 남길 증거

- 사용자 요청 ID↔Job↔GPU 노드↔결과 파일을 추적
- 시연 화면과 측정값의 실제 여부를 명시

## 서술형 인출 질문

1. 왜 서비스 시연과 배치 공유 실험을 분리해야 하는가?
2. 프론트엔드에서 성공으로 보인 작업이 실제 GPU 작업이었다는 근거는 어떻게 제시하겠는가?
