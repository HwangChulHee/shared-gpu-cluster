# Lab 02-02 — GPU 서버의 스토리지·네트워크 데이터 경로

> **2026-11-13 Linux GPU 서버 중심 교안** · 환경: **L+G1** · 실제 GPU 실험 미완료. [이관표](../migration-2026-11-13.md)에서 이전 번호를 확인한다.

## 실제 운영 요구와 학습 목적

학습 데이터 다운로드, 재사용, 업로드는 GPU 밖에서 일어난다. S3·EBS·VPC·IAM·SG를 별개로 설계하고 원인별로 진단해야 한다.

## 내부 동작·책임 분리

`S3 원본 ↔ IAM/SG/VPC/엔드포인트 또는 NAT ↔ EC2 ENI ↔ EBS/로컬 디렉터리 ↔ YOLO 로더`

## 학습 및 직접 실습

1. 데이터셋 저장 위치, 파일 수·총 크기, S3 Bucket/Key, EC2 IAM Role을 정하고 VPC 라우팅/SG/인스턴스 프로파일 경로도 작성.
2. L에서 Terraform/S3 정책과 비용 게이트, 최소 권한·보안·종료 체크리스트 작성. GPU가 필요 없는 네트워크·S3 준비는 가능한 한 GPU 가동 전에 한다.
3. G1 호스트에서 실제 자격 증명 노출 없이 S3 데이터 접근과 EBS/파일시스템 용량 확인. `aws s3 ls`, `aws s3 cp` 같은 명령의 실제 결과·전송 시간 기록.
4. S3 다운로드/로컬 읽기/결과 업로드 경로를 분리하며, 실패 시 IAM 403·네트워크 타임아웃·스토리지 부족을 각각 구별.
5. EBS와 S3 보존·삭제 정책, 네트워크 사용·비용 정리.

## 완료 판정에 필요한 실제 증거

VPC/S3 데이터 경로·IAM 근거, 전송·저장 위치·크기/시간, 권한/네트워크 진단, 비용·정리 기록.

GPU/EKS 실행 전 **G/VT 쿼터 8 vCPU 적용 확인**과 별도로 EC2 AZ 용량·AMI·실제 가격·EBS/S3/NAT/IPv4 부대 비용·리소스 삭제 계획을 검토한다. 준비되지 않으면 L 이론만 진행하고 GPU 실습은 **대기**로 표시한다. 예상과 실제 출력은 구분한다.

## 서술형 질문 (답변 후 다음 개념)

GPU EC2에서는 인터넷 접속이 되는데 특정 S3 객체를 못 읽는다면 IAM과 네트워크 중 무엇부터 어떻게 구별할까?
