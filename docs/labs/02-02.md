# Lab 02-02 — EKS와 노드 그룹

> **학습 교안 / 미실행**. 실행 절차는 실제 AWS/패키지 버전에 맞춰 고정한 뒤 수행합니다. 예상 결과는 실측 결과가 아닙니다.

## 학습 맥락과 목표

GPU Node에 Grafana가 배치돼 고가의 GPU 인스턴스 비용을 잡아먹거나, 시스템 Pod가 GPU 노드만 남을 때 장애에 영향을 받지 않도록 시스템/연산 워크로드를 분리한다.

## 핵심 개념·원리

1. EKS Managed Control Plane은 AWS가 Kubernetes API Server 등 핵심 제어 구성 요소를 관리하는 구조다. Worker Node의 용량·스케일링·OS 업데이트와 Pod 스케줄링은 별도 운영 영역이다.

2. CPU 노드는 API·메트릭·시스템 서비스를, GPU 노드는 GPU Job을 맡는 방향으로 분리한다. Label과 taint/toleration을 이용해 배치 정책을 명시한다.

3. GPU 인스턴스 두 대를 같은 Node Group에 두더라도 실제로 서로 다른 노드인지, 가용 영역이 어떻게 분포되었는지는 실측해야 한다. 노드 장애 복구와 멀티 AZ 무중단은 동일하지 않다.

## 내부 흐름

Terraform → EKS Cluster 생성 → CPU/GPU Managed Node Group → kubelet 등록 → Node Ready/Label/Taint → 워크로드 배치.

## 실습 준비

EKS 비용·쿼터·AMI 및 세션 종료 기준을 Phase 01에서 확인. GPU 노드 개수 2대를 배치할 수 있는 계정 한도 확인.

## 실습

1. CPU 시스템 Node Group과 2개 GPU Worker를 Terraform으로 만든다.
2. `kubectl get nodes -o wide` 및 `kubectl describe node`로 노드별 GPU/CPU/라벨/taint 조사.
3. GPU 노드가 없어도 일반 시스템 Pod가 CPU 노드에서 운영되도록 배치 규칙 검증.

## 검증할 증거

- 서로 다른 GPU Node 2대의 Node Ready·Instance ID·AZ 확인
- 비용 발생 자원 목록과 삭제 방법 기록
