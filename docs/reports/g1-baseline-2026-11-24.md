## 2. YOLO 기준선 — baseline-01

| 항목 | 실측 값 |
|---|---:|
| 모델 | YOLO11n |
| Epoch / Batch / Worker | 3 / 8 / 2 |
| 이미지 크기 / seed | 640 / 42 |
| 학습 이미지 / 검증 이미지 | 900 / 100 |
| 실행 구간(UTC) | 2026-11-24 07:51:30.928880 ~ 07:52:38.179996 |
| 실행 구간(KST) | 2026-11-24 16:51:30 ~ 16:52:38 |
| 종료 코드 | **0** |
| 총 Wall time | **67.251 s** |
| End-to-end 처리량 | **40.148 train images/s** |

처리량 계산: `900 × 3 / 67.251 ≈ 40.148`. **초기화·학습·검증·체크포인트를 포함하는 전체 실행 시간**이 분모이며 CUDA 커널 처리량이나 초당 추론 이미지 수와 동의어가 아니다. 이 COCO 부분집합은 성능·재현성 실험을 위한 것으로 **정확도 대표성을 보장하지 않는다**. `exit=0`과 산출물 생성으로 정상 학습 실행을 확인했지만, Epoch별 상세 시간은 별도 분석하지 않았다.

### Prometheus 모니터링 관측

G1의 Node Exporter `9100` / DCGM Exporter `9400`를 Docker Compose로 기동하고 로컬 Prometheus에 `g1-node`, `g1-dcgm` target 등록. 실제 `up=1` 및 `lastError=""`, 스크레이프 15초 간격 검증.

학습 구간을 `query_range`(15초 step)로 조회해 저장한 **각 5개 샘플** 기준:

| 지표 | 평균 | 최대 |
|---|---:|---:|
| `DCGM_FI_DEV_GPU_UTIL` | **10.20%** | **51.00%** |
| `DCGM_FI_DEV_FB_USED` | **1,041.60 MiB** | **2,148 MiB** |
| `DCGM_FI_DEV_GPU_TEMP` | 메트릭 JSON 저장 | 미집계 |

메트릭 JSON은 로컬 WSL의 `artifacts/benchmark/baseline-01/metrics/{gpu-utilization,gpu-memory,gpu-temperature}.json`에 저장. **GitHub 커밋 또는 S3 업로드는 아직 확인되지 않았다.** 샘플 5개만으로 안정 상태 GPU 활용률, 특정 병목, 배치 확장에 따른 개선을 확정할 수 없다. 별도로 최근 2분 Instant Query 평균 `12.75%`, 최대 VRAM `2148 MiB`가 출력됐으나 조회 시각이 달라 학습 구간 집계와 혼합하지 않는다.

## 3. 실제 장애와 해결

1. **Ultralytics import 시 `libGL.so.1` 누락:** GUI 의존 `opencv-python` 제거 후 `opencv-python-headless==5.1.0.95` 설치. 이후 `cv2`/PyTorch/Ultralytics import, CUDA 인식 및 YOLO 추론 성공.
2. **Ubuntu apt `awscli` 후보 없음:** AWS CLI v2 공식 zip 설치 후 `aws-cli/2.42.2` 확인. `aws sts get-caller-identity`가 `assumed-role/g1-gpu-ec2-role/i-0594331269a4fefa5` 반환. 별도 장기 Access Key를 G1에 복사하지 않음.
3. **G1에서 보안 그룹 수정을 시도하여 `UnauthorizedOperation`:** 권한이 제한된 인스턴스 Role의 정상적인 거부. 로컬 WSL의 관리 IAM User에서만 9100/9400 규칙 생성.
4. **외부 Scrape Timeout:** 9100/9400 인바운드를 현재 공인 IP `59.13.207.3/32`로 제한해 허용한 후 `Node: OK`, `DCGM: OK` 확인.
5. **Prometheus `promtool` 실행 방식 오류:** 컨테이너의 기본 엔트리포인트가 `prometheus`였으므로 `--entrypoint /bin/promtool`로 정정, 설정 문법 `SUCCESS`.
6. **첫 Prometheus `up` 조회가 `result=[]`:** 이후 Target API에서 두 Job 모두 `health=up`, 쿼리 `up=1` 확인. 초기 조회 당시에는 해당 시계열이 조회되지 않음.
7. **로컬 WSL에서 GPU 벤치마크 명령 실행:** `~/gpu-venv` 미존재·`python` 명령 없음. G1 SSH에 재접속해 올바른 환경에서 실행 성공.

## 5. 다음 검증과 제한

- G1 첫 GPU ON에 **Batch 8 / Worker 2 기준선은 1회**만 실행. Batch 16/32, Worker 비교, 고의 GPU OOM 및 checkpoint resume **미수행**.
- 단 5개의 DCGM 시계열 샘플만으로 CPU/DataLoader 병목이라고 결론 내리지 않는다. 다음 실험에서 고빈도/전체 구간 메트릭, CPU 지표, CUDA 학습 시간, 반복 측정 및 비교군 필요.
- Docker GPU 인식 검증과 **호스트 venv 기반 학습**을 구분한다. Kubernetes/EKS GPU Worker와 Terraform 재현 검증은 아직 수행하지 않았다.
- 다음 GPU 비용 지출 전에 잔존 과금 자원/메트릭 보존/G1 재현성 계획 검토.
