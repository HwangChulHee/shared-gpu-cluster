# AI/GPU 인프라 운영 학습·실습 커리큘럼

> **2026-11-13 개편 · 7 Phase / 21 Lab**. Linux GPU 서버·시스템 운영이 본 과정이고 EKS는 그 환경을 확장하는 계층입니다. 모든 GPU 실습·장애 실험은 계획이며 실제 실행 여부는 [진도표](../learning/progress.md)를 따릅니다.

## 프로젝트 목표

가상의 AI 연구팀에게 GPU 학습 실행 환경을 제공한다는 요구사항을 바탕으로 **단일 NVIDIA GPU Linux 서버의 구성·데이터 경로·운영 메트릭을 먼저 검증**한다. 이후 이를 EKS GPU 클러스터로 확장해 Job 및 Worker 운영을 검증하고, 실제 공개 사례를 근거로 성능·장애를 분석한다. YOLO는 **인프라 검증용 단일 워크로드**다.

- 환경: **L** 로컬·이론, **G1** 단일 GPU EC2, **G2** EKS + GPU Worker 2대, **O** 오프라인 분석. G1/G2는 동시에 켤 필요가 없다.
- 비용·안전: 서울 On-Demand G/VT 8 vCPU **승인·적용 확인**. 실행 전 AZ 가용성·AMI·리소스별 예상 과금과 삭제 경로 점검. 한 단계 이론·실험표·콘솔 구축/삭제 체크리스트 준비 → 짧은 G1 콘솔 GPU 세션 → 측정 → 결과 보존 → 수동 삭제/잔여 과금 점검 → 별도 Terraform 재현성 검증.
- 학습: **개념 하나 → 서술형 질문 하나 → 답변·피드백 → 다음**; 기존 학습과 중복 시 진단에 필요한 새로운 요소만 배운다.
- 검증: **정상 기준선 → 가설/반증 조건 → 실제 계측 → 비교 → 한계·복구**. 공개된 자연 발생 운영 사고와 의도적 장애 주입을 구분한다.
- 필수에서 제외: 웹 UI/API, Gemma/XGBoost, Slurm, MIG, 분산 학습, Kueue 고급 자원 공유 정책.

## 실제 실행 순서 — 이론 순서와 AWS 비용 세션 구분

**Lab 번호는 학습·보고서 분류용이며 AWS 자원의 가동 순서를 강제하지 않습니다.** 유료 리소스를 최소화하기 위해 아래처럼 묶어 진행합니다.

| 실행 세션 | 수행할 Lab | 운영 목표 |
|---|---|---|
| **사전 준비(L/O)** | 01-02, 01-03 준비, 02-01~03-03 준비, 04-01 설계, 07-01 콘솔 구성 기록·향후 G1 Terraform 재현 계획 | GPU를 켜기 전 이미지·데이터·스크립트·실험표·비용·삭제 계획 확정 |
| **G1: 단일 Linux GPU 서버** | 01-03, 02-01~03, 03-01~03, **06-01·06-02**, 07-01 G1 재현성 점검 | 실행·데이터·계측·성능 비교/안전한 OOM 실험을 한 묶음으로 완료 |
| **G2: EKS GPU Worker** | 04-02~03, 05-01~03, **06-03·06-04**, 07-01 G2 재현성 점검 | Device Plugin·Job 운영·노드 장애·메트릭 확장 |
| **마무리(O)** | 07-02 | 실측 결과와 운영 보고서·RCA·Runbook 정리 |

**중요:** 06-01/06-02는 문서상 Phase 06이어도 G1을 종료하기 전에 실행합니다. Phase 06의 G1/G2 실험을 번호 순서대로 재구축하지 않습니다. G1 첫 콘솔 세션에서는 구성값·실험 로그·메트릭을 외부에 보존하고 수동으로 리소스를 삭제합니다. 이후 별도 짧은 Terraform 재현 세션에서 apply/destroy를 검증합니다. G2는 계획된 IaC 방식에 따라 정리하되 모두 잔여 비용을 점검합니다. GitHub/원격 Terraform state 저장 경로에 자격 증명이나 개인정보를 넣지 않습니다.
