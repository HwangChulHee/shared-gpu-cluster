## 변경 이유

GPU 스케줄링 정책 개발보다 AI 인프라 엔지니어에게 필요한 **Linux 서버, NVIDIA Driver/CUDA, 프로세스·메모리·I/O, S3/EBS·네트워크, GPU 관측, 클러스터 확장, 실제 운영 사례 기반 문제 진단**을 우선한다. YOLO는 동일한 실험을 여러 계층에서 반복 검증할 대표 워크로드이지 서비스 개발 목표가 아니다.

## 번호·진도·과금

- **이전 원형 29 Lab:** [2026-11-12 이관표](migration-2026-11-12.md) 및 Git 히스토리.
- **과거 평가:** `learning/records/01-01.md`, `01-03.md`, `01-04.md`, `01-05.md` 등은 작성 당시 내용을 유지한다. 번호가 같더라도 새 Lab 평가로 전환하지 않는다.
- **현재 개편 이후 새 평가:** `learning/records/v3/<id>.md`에 저장한다. v2 경로를 포함한 이전 가이드의 설명보다 **v3가 우선**한다. 동일 내용의 이전 개념 점수는 선수 학습 참고자료.
- **기존 실측:** GPU 인스턴스와 EKS를 실행해 본 기록 없음. 01-01 기초 이론·시나리오만 완료, 01-02 GPU 쿼터 적용 확인·비용 게이트 미완료, 01-03 GPU 실습 대기.
- **비용:** G/VT 8 vCPU는 실제 승인·적용됨. EC2 실행 여부·실제 AZ 사용 가능성은 별도 검증.
