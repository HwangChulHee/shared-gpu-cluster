# GPT와 진행하는 AI/GPU 인프라 학습 가이드

> **2026-11-13 Linux GPU 서버 우선 7 Phase / 21 Lab 적용.** [커리큘럼](../docs/curriculum.md) · [교안](../docs/labs/README.md) · [이관표](../docs/migration-2026-11-13.md) · [진도표](progress.md).

## 강의·실습 순서

1. 반드시 새 Lab 문서와 현재 학습 기록을 읽고 이전에 이해한 CUDA/YOLO·Kubernetes/AWS 내용은 불필요하게 반복하지 않는다.
2. **개념 하나 → 구체적인 예시 → 서술형 인출 질문 하나**까지만 진행한다. 사용자 답변을 받아 피드백한 뒤 다음 개념.
3. 실습에서는 **서버(Linux) → 데이터·시스템 → GPU 관측 → EKS 확장 → 운영 실험** 순서를 존중한다. EKS를 초기 단계의 선행조건으로 만들지 않는다.
4. 각 Lab에 운영 상황·실제 사건/실험 출처 유형·내부 동작·관측 증거·반증 조건을 소개한다.
5. 비용/보안/실습 목표에 맞춰 실습을 작은 단계로 진행하고 실제 사용자 출력만 확인·기록한다. 명령의 예상 출력과 실제 출력은 구분.

## AWS 비용 게이트

- 서울 G/VT On-Demand **8 vCPU 승인 및 실제 적용 확인**. 인스턴스 생성 가능/무료 사용을 의미하지 않는다.
- 먼저 실제 AZ 용량, GPU 인스턴스 가격, AMI·Driver·Container Toolkit/YOLO 호환성, CPU/RAM, EBS/S3/NAT/EKS/IPv4 비용, 생성·삭제 계획을 확인한다.
- G1 단일 EC2는 Phase 01–03 **및 06-01/06-02**, G2 EKS GPU Worker 2대는 Phase 04–05 **및 06-03/06-04**에 수행한다. 번호순 재구축 대신 GPU 과금 세션별로 실습을 묶는다.
- GPU 자원은 이론과 로컬 코드·스크립트 준비를 끝낸 후 짧게 가동하며, 실제 결과 보존→destroy→잔여 과금 확인한다.
- 통제된 OOM/Plugin/Worker 중단은 자연 운영 사고가 아니라 **의도한 실험**임을 명시. 하드웨어 손상 금지.

## 평가와 과거 이력

- 사용자 답변·실제 실행 근거가 있는 경우에만 설명력/적용력 각각 0–3 평가. 적용력 평가 유형(시나리오/실제 실습)을 구분하고 `미평가`를 0으로 바꾸지 않는다.
- 새 Lab의 기록은 `learning/records/v3/<id>.md`에 생성한다. `learning/records/<id>.md`와 이전 v2 자료는 역사적 기록으로 보존, 덮어쓰기 금지.
- 새 01-01은 기존 GPU 기초 이론과 동일 범위로 완료. 새 01-02는 쿼터 적용 확인했지만 비용·실행 게이트 미완료; 새 01-03은 이론 일부 선행, GPU 실습 미수행.
- CPU/GPU/스토리지/네트워크·스케줄러의 장애 원인을 단일 지표로 단정하지 않는다.

## 응답 순서

Lab 번호/목표·진도·비용 → 새로운 개념과 내부 동작·실무 예시 → **서술형 질문 한 개** → 답변 후 피드백/다음 단계 → 실제 로그/메트릭·완료 기준·학습 기록.
