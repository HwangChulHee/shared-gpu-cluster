# 이해도·학습 결과 기록 방식

목적은 단순 진도 체크가 아니라 **학습 직후 설명 가능한지, 실제 운영 문제에 적용 가능한지, 무엇을 복습해야 하는지**를 추적하는 것입니다. 학습자의 이해도는 답변과 실습 증거를 기반으로 기록하며 추정하지 않습니다.

## 섹션별 진행 순서

1. **사전 이해 점검:** 이미 알고 있는 것과 헷갈리는 것 한두 문장 (선택)
2. **이론/사례:** 내부 동작과 사용 맥락 학습
3. **인출:** 힌트 없이 서술형 질문 1~3개에 답변
4. **피드백:** 정답 설명보다 오개념·누락된 연결 고리를 우선 교정
5. **실습:** 예상 동작을 적고 직접 구성·로그·메트릭 검증
6. **학습 기록:** 실습·인출 결과와 이해도, 남은 질문, 다음 복습 과제 기록

## 평가 기준 (측정 증거와 자신감 분리)

| 척도 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| **개념 설명력** | 핵심 설명 불가 | 단편적 이해/큰 오개념 | 대체로 정확하나 빈틈 있음 | 내부 흐름·제약·근거를 자기 언어로 설명 |
| **실전 적용력** | 접근 불가 | 도움 없이는 적용 어려움 | 일부 힌트 또는 사소한 수정으로 적용 | 예상·진단·검증을 스스로 수행 |

**총점 0~6:** 0~2 보완 필요 / 3~4 부분 이해 / 5~6 안정적 이해. **두 항목이 실제로 모두 평가되었을 때만** 합계를 산정합니다. 설명력만 평가했다면 적용력은 **미평가**이며 0점으로 환산하지 않습니다. 점수는 인출·실습·진단의 관측 근거로만 부여합니다.

**자기 자신감 1~5:** 사용자가 별도 기록합니다. 평가 점수와 일치할 필요는 없습니다.

**실습 상태:** 미시작 / 준비 / 진행 중 / 성공(근거 링크) / 실패·재시도 / GPU 환경 미확보. 이론 완료를 실습 완료로 합산하지 않습니다.

**최종 섹션 상태:**
- 미시작: 학습·실습 없음
- 진행 중: 이론/답변/실습 중 일부만 수행
- 보완 필요: 점검에서 주요 오개념 또는 핵심 검증 실패
- 완료: 필수 인출 답변과 실습 검증이 충족된 상태
- 대기(GPU): 개념 학습은 진행했으나 실제 GPU 검증이 미완료

## 기록 및 갱신

- `learning/progress.md`: 전체 Lab의 이론/실습 상태, 설명력·적용력, 보완 과제와 복습 시점 확인
- `learning/records/PHASE-LAB.md` 형식: **실제로 해당 섹션을 진행한 후에만** 파일 생성
- `learning/section-template.md`: 기록 양식 복사 원본
- 문서에는 답변 요약·오개념·증거 링크만 기록해 과도한 대화 전문 복사 방지
- 복습 시 기존 기록을 덮어 지우지 않고 **재평가 날짜/점수/변화**를 누적
- **섹션 상태**는 최종 완료 판정과 구별해 진도표에 표시하고, GPU 실습 대기 상태에서는 설명력과 적용력을 별도로 기록
- 복습 권장 시점: 다음 학습 세션, 3~7일 뒤, 장애 실험에서 동일 개념 재사용 시. 실제 일정은 유연하게 조정
- 진도는 실습 성공이나 이해도를 임의로 추정하지 않고 사용자와 함께 검증한 결과만 기록

## 한 번의 학습 종료 예

```text
Lab: 02-03
개념 설명력: 2/3 (Driver→Device Plugin 관계는 정확, kubelet 연결 불명확)
실전 적용력: 1/3 (로그 진단에 힌트 필요)
실습: 진행 중
자기 자신감: 3/5
보완: GPU Capacity/Allocatable 생성 경로
다음: kubelet·Device Plugin 연결 다시 설명 후 Pod Events 재검증
```

이 예시는 **가상의 기록**이며 실제 학습자의 평가 결과가 아닙니다.
