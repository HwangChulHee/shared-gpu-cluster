# Lab 01-01 — GPU 컴퓨팅 기초

> 상태: **완료 (이론·시나리오 평가)**  
> 학습일·평가일: 2026-11-12 · 환경: L (대화형 이론·사고실험)  
> 실제 GPU 실습: **미실시 (이 Lab의 필수 요건 아님)**

## 목표와 학습 내용
- CPU(복잡한 제어 흐름·지연 최적화)와 GPU(다량의 독립·유사 연산의 병렬 처리)의 차이 이해
- 모델 가중치 외 KV Cache, 중간 연산, 런타임 공간 등 VRAM 추가 사용 요인 설명
- 스토리지 → CPU 전처리/RAM → PCIe → GPU VRAM/연산 흐름에서 병목 위치 추론

## 서술형 인출 및 적용 평가 (사용자 답변 요약)
1. **이미지 10만 장 분석에 GPU가 유리한 이유**: 복잡한 로직보다 반복되는 유사 작업을 GPU의 많은 연산 유닛으로 병렬 수행하기 적합하다고 설명. 피드백: 반복 자체보다 *독립적인 병렬 수행 가능성*이 핵심임을 보충.
2. **16GB VRAM에서 14GB 가중치 모델의 OOM**: KV Cache, 런타임 메모리와 중간 계산 결과가 추가 공간을 사용한다고 정확히 설명.
3. **YOLO GPU 사용률 15%인데 학습이 느린 상황**: CPU에서의 데이터 준비 또는 CPU↔GPU 전달 경로에서 병목 가능성을 제시.
4. **병목 위치 구분 방법(후속 적용 문제)**: 스토리지 데이터 읽기 시간, CPU 처리 시간, GPU 작업 시간 등을 **단계별로 측정·비교**하겠다고 제시. 피드백: PCIe 전송시간도 별도로 계측하고, 처리 단계 간 겹침을 고려해야 함을 보충.

## 실습·검증
- 실제 AWS·GPU 자원 실행: 없음. 발생시킨 클라우드 비용: 없음.
- 평가 유형: **시나리오 기반 적용 문제**.
- 검증된 능력: CPU/GPU 병렬성, VRAM 구성, 데이터 파이프라인 병목의 원인 추정 및 구간별 시간 계측 계획.
- 검증하지 않은 능력: 실제 GPU 프로파일러 사용·PCIe 전송량 측정·YOLO 학습 환경 구축. 수행한 것으로 기록하지 않음.
- 실습 상태: **해당 없음(이론 전용)**.

## 이해도 평가
- 개념 설명력: **3/3** — CPU/GPU 차이와 VRAM 부가 사용을 자신의 언어로 정확히 설명.
- 적용력: **3/3 (시나리오 기반)** — GPU 저사용률 원인과 단계별 시간을 관찰하는 진단 방향을 스스로 제시.
- 합계: **6/6** (실제 GPU 실기 점수가 아님).
- 자기 자신감: **미기록** (사용자가 별도로 평가하지 않음).
- 섹션 상태: **완료**.
