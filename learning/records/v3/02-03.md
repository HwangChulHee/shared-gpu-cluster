# Lab 02-03 — YOLO DataLoader·Checkpoint 기본 운영 (v3)

- 기록일: 2026-11-18
- 상태: **GPU OFF-1 로컬 기준선·DataLoader 멀티프로세싱 검증 완료 / GPU ON 실제 G1 학습·재개 및 OFF-2 분석 대기**
- 환경: WSL Ubuntu, uv, Ultralytics 8.4.211, PyTorch 2.15.0+cpu, Intel Core i5-14500
- **GPU 실측 없음**. 과거 CPU 체크포인트 중단·Resume 및 S3 체크섬 검증은 기존 증거 재사용.

## 핵심 이해

- SSD/EBS의 이미지·라벨을 DataLoader가 읽어 전처리·배치 생성 후 모델 연산에 공급한다. CPU 데이터 준비 지연은 GPU 대기를 초래할 수 있으나 GPU Util 하나로 원인 확정 불가.
- `workers`는 데이터 로딩 프로세스 수, `batch`는 배치 크기, `imgsz`는 입력 이미지 크기, `cache`는 데이터 캐시 전략에 영향.
- 시스템 RAM 부족과 GPU VRAM 여유가 동시에 존재할 수 있다. `cache=True` RAM 이미지 캐시를 우선 확인하되 원인 확정은 관측 필요.
- 완료 후 Ultralytics가 optimizer를 제거한 `last.pt` / `best.pt`와 중단 학습 재개용 optimizer 포함 체크포인트는 구별.

## YOLO CPU 1 epoch 기준선 — 사용자 실행 로그

- 모델 `yolo11n.pt`, COCO8 학습 4장·검증 4장; `epochs=1`, `batch=4`, `imgsz=640`, `cache=False`, `device=cpu`, 요청 `workers=2`.
- **실제 YOLO 로그는 `Using 0 dataloader workers`**. `args.yaml`에는 요청값 `workers: 2`. 요청 설정과 실사용 숫자를 구분함.
- 학습 1 Epoch 정상 완료, 결과 저장 `runs/detect/artifacts/dataloader/cpu-baseline/`, `last.pt`·`best.pt` 각각 약 5.3MiB (파일 표시 5.3M). 두 파일 모두 `Optimizer stripped` 로그 존재.
- `/usr/bin/time -v`의 전체 실행 elapsed `2:22.09`, max RSS `1965272 KB` (약 1.87GiB), Exit status `0`.
- Epoch 학습 1 batch 약 0.7초. **전체 142초는 학습뿐 아니라 초기화·데이터 스캔·검증 등 포함**. 세부 단계별 소요 시간 미측정.
- `find artifacts/dataloader/cpu-baseline` 경로 확인 실패는 학습 실패가 아니라 실제 저장경로가 `runs/detect/artifacts/dataloader/cpu-baseline/`였기 때문.

## PyTorch DataLoader 독립 멀티프로세싱 검증 — 사용자 실행 로그

- `Dataset` 8개 원소, `batch_size=2`, `num_workers=2`, 데이터당 `sleep(0.2)`, 각 `__getitem__` 처리 PID 반환.
- Main PID: `36022`; Worker PIDs: `36042`, `36043`.
- 4개 배치 각각 `[0,1]`→36042, `[2,3]`→36043, `[4,5]`→36042, `[6,7]`→36043.
- 결과: **PyTorch DataLoader의 서로 다른 2개 Worker 프로세스 생성·배치 분산 처리 확인**. YOLO의 실제 Worker 수 0과 구분하며, 처리량 개선은 측정하지 않음.
- 테스트 파일 `/tmp/test-dataloader.py`는 임시 경로이며 GitHub 커밋 대상 아님.
