# Lab 03-01 — NVML·DCGM GPU 관측 (v3)

- 기록일: 2026-11-19
- 상태: **GPU OFF-1 이론 및 수집 스크립트 구문 확인 완료 / G1 GPU ON 실측·OFF-2 분석 대기**
- 환경: WSL Linux, Bash. 실제 NVIDIA L4 장치 계측은 아직 수행하지 않음.

## 이론·인출 (대화형 학습)

- NVML은 GPU 드라이버의 관리·관측 API, `nvidia-smi`는 GPU 상태 CLI, DCGM은 GPU 모니터링/진단 도구이며 exporter 연계 가능.
- GPU Util은 GPU 커널 활동을 관측한 비율로 최대 FLOPS 달성률이 아님. SM Active는 활성 Warp가 존재하는 SM 사이클의 비율, SM Occupancy는 SM 상주 Warp 수 / 최대 상주 가능 Warp 수. Tensor Active는 Tensor Core 파이프라인 활동률.
- VRAM 점유량 ≠ DRAM 인터페이스 활동률 ≠ DRAM 전송 처리량. NVIDIA L4 VRAM은 GDDR6 기반.
- Power Draw와 Power Limit, GPU Temperature와 SM Clock을 함께 보고 전력/온도 제한에 따른 Throttling 가능성을 조사하되, 원인·처리량 변화는 실제 로그 없이 단정하지 않음.
- CPU Util vs 실제 명령어/작업 처리량을 비교해 GPU 활동률과 처리량의 차이를 설명; 높은 SM Active/VRAM만으로 연산 포화나 메모리 병목 확정 불가.
- 질문 응답: VRAM이 높고 GPU Util이 낮을 때 데이터 공급·코드 대기 등 가설 제시, DRAM Active 낮음은 저장 데이터 양이 아닌 메모리 활동량임을 구별, 열·전력으로 클럭 제한 발생 시 처리량 감소 가능성 및 클럭/온도/제한 원인 확인을 설명. 개별 질문에 대한 정량 평가는 미실시.

## 로컬 사전 검증 — 실제 사용자 실행

- `scripts/collect-gpu-metrics.sh` 파일 GitHub `main` 반영 (최초 커밋 `9603f2e`), [스크립트](../../../scripts/collect-gpu-metrics.sh).
- 스크립트: 사전 `nvidia-smi` 지원 쿼리 확인, timestamp/GPU Util/VRAM/온도/전력/SM clock을 CSV 저장, 샘플 수·간격·경로 인자.
- 사용자가 실행: `bash -n scripts/collect-gpu-metrics.sh` → `Syntax exit code: 0`.
- **검증 범위:** Bash 구문에 한함. nvidia-smi 옵션/실제 필드 지원, CSV 값, DCGM, G1 처리량은 **미검증**.
- CSV 기본 위치 `artifacts/gpu-metrics/`는 Git 제외. 유료 G1 종료 전에 데이터 보존 필요.

## G1 GPU ON / OFF-2 후속 과제

1. G1 GPU에서 `nvidia-smi` 사용 가능 여부·실제 필드 지원 확인.
2. YOLO 시작/실행/종료에 걸쳐 GPU 지표 CSV 원본 수집; 측정 간격과 내부 집계 창 차이 기록.
3. 지원되는 DCGM SM/Tensor/DRAM 지표를 확인하고 Lab 03-02 exporter/Prometheus로 수집.
4. 메트릭 원본 보존, 프로세스·CPU·데이터로더 지표와 비교, GPU 리소스 삭제 후 분석.
