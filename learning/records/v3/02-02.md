# Lab 02-02 — GPU 서버의 스토리지·네트워크 데이터 경로 (v3)

- 기록 기준일: 2026-11-18
- **상태:** GPU OFF-1 네트워크·IAM·S3 이론 및 로컬 전송 검증 완료. **G1 실제 IAM Instance Profile/EBS 데이터 경로 실측 및 OFF-2 대기**.
- 환경: WSL Ubuntu 24.04, AWS CLI, 서울 리전 `ap-northeast-2`; AWS 인증 주체는 로컬 IAM User `Logan`. **EC2 Role 자격 증명 검증으로 간주하지 않음**.

## 학습·인출 결과

- S3 객체 스토리지와 EC2 EBS 블록 스토리지의 역할, EC2 종료 시 `DeleteOnTermination`에 따른 EBS 보존 여부, S3 독립 보관 목적 설명.
- S3 API 통신은 주로 HTTPS TCP 443 아웃바운드. Stateful Security Group 응답 트래픽, Public EC2/IGW와 Private EC2/NAT Gateway/S3 Gateway Endpoint의 경로 구별.
- S3 Gateway Endpoint는 Docker Hub 외부 접속을 대체하지 못함. G1 로컬 계획은 Public Subnet + 제한된 SSH + IAM Role; 포트폴리오 최종 보안 구성과 구별.
- Instance Profile ↔ IAM Role ↔ IMDS의 임시 자격 증명 관계, 로컬 credentials 및 AWS CLI 자격 증명 선택의 차이 학습.
- S3 `403 Forbidden`은 경로 연결이 이뤄진 경우 정책·권한을 우선 점검; S3 도달 실패/타임아웃, EBS 공간·권한 문제와 구별.
